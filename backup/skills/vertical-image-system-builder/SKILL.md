## 全栈后端硬门禁（强制，不得只做前端逻辑）

本技能默认交付的是**前端 + 后端 + 数据层**的可运行垂直业务系统。除非用户明确要求“仅做不可交付的前端原型”，否则不得用 Pinia、localStorage、静态 JSON、`setTimeout` 假成功或浏览器内存状态替代后端。

### 1. 后端必须真实存在

每个项目必须有可启动的后端工程或服务端入口，优先复用现有后端；没有后端时默认补齐与前端同仓的 FastAPI/Node 等真实服务。至少包含：

- 业务 API 路由、请求/响应模型、参数校验和统一错误响应；
- 领域服务、规则计算或算法处理层，不能把核心判断全部写在 Vue 事件处理器里；
- 数据库或等价持久化层，默认可用 SQLite 开发库，生产型项目按实际需要使用 PostgreSQL/MySQL 等；
- 表结构/实体模型、初始化数据、迁移或可重复初始化脚本；
- 登录、会话或令牌、角色权限和接口级鉴权；
- 操作留痕、错误日志、健康检查和环境配置；
- 后端单元测试或接口集成测试，至少覆盖成功、校验失败、无权限和业务异常分支。

### 2. 前端必须通过接口使用后端

- 主要业务链路必须由前端调用真实 HTTP API 完成，Pinia 只负责缓存、视图状态和交互编排，服务端是业务状态与持久化结果的权威来源。
- 登录后必须得到真实会话/令牌；刷新页面或重新启动前端后，已保存的业务对象、任务状态、审核结果、归档版本和操作留痕能够从后端重新读取。
- 新增、编辑、校核、审核、派发、回退、复查、封存和查询等动作必须有对应 API、数据库变化或可验证的业务结果。
- 前端可以保留加载态、错误态和离线提示，但不得把本地模拟数据当成已接入后端的生产结果；任何暂未接入的能力必须在界面和验收记录中明确标注。

### 3. 后端最小工程交付

项目源码中必须能找到与实际运行一致的后端结构，例如：

```text
backend/ 或 server/
├── app/main.py / src/server.ts       # 服务入口与健康检查
├── api/                              # 路由、鉴权和请求响应模型
├── domain/ 或 services/              # 领域规则、算法和状态流转
├── models/ 或 repositories/          # 实体、数据库访问和持久化
├── migrations/ 或 db/                # 表结构、迁移或初始化脚本
├── tests/                            # API/领域/权限测试
└── .env.example、README.md           # 配置与启动说明
```

目录名可按项目技术栈调整，但职责必须齐全；不能只放一个返回静态 JSON 的 `server` 文件冒充后端。

### 4. 端到端后端验收

至少走通一条真实闭环：登录/鉴权 → 查询业务对象 → 创建或更新 → 执行规则/算法 → 状态流转 → 审核或派发 → 回退/复查 → 归档 → 查询操作留痕。验收必须记录：

- 前后端启动命令、端口、环境变量和数据库初始化命令；
- API 请求、响应状态码、关键响应字段和数据库变化；
- 登录、权限不足、参数错误、业务冲突、重复提交和服务异常分支；
- 刷新页面、重新登录或重启服务后的持久化复核；
- `设计说明.md` 的接口与数据流、`验收记录.md` 的接口测试结果、`操作手册.md` 的真实操作步骤。

只通过 `npm run build`、只看到页面变化、只使用浏览器内存数据或只验证前端截图，均不能视为全栈验收通过。

### 5. 明确禁止

- 禁止把“前端模拟”“本地假接口”“静态 JSON”“localStorage 全量业务状态”“按钮 toast”写成后端已完成；
- 禁止使用无数据库写入的假保存、无鉴权的假登录、无权限判断的假审核和无版本关系的假归档；
- 禁止后端只提供健康检查而不承载真实业务链路；
- 禁止前端和后端各写一套互不相连的数据模型、状态枚举和字段名；
- 后端未完成时必须如实标注缺口并继续实现，不得进入最终交付话术。

## 真实开发、开发留痕与代码文档调整硬门禁

以**完整开发者的视角**完成每个项目：需求、设计、编码、自测、验收、部署、文档都要真实发生并留下记录，任何交付物都必须能追溯到真实开发过程。禁止用虚拟图、生图、无关内容或跑不通的流程充当完成。

### 1. 真实开发（以真实环境为基准）
1. 每个页面、按钮、状态、流程都必须真实存在且真实可运行；至少从登录进入开始把一条核心业务链路**端到端走通**，并在 `验收记录.md` 留下轮次、命令和结果。

### 1-A. 真实截图与高清截图硬门禁（必须检查）
以下检查必须在截图采集、操作手册生成、验收和交付前逐项执行：
1. 截图必须来自当前项目当前运行版本的实际浏览器/客户端；禁止生图、设计稿、旧项目、静态 mock、无关网页、拼接图或重新绘制的“界面图”替代。截图前在 `验收记录.md` 记录运行地址、版本、登录角色、页面/状态和采集时间。
2. 必须覆盖登录页、首页/主三维工作台、全部业务页及关键操作后状态；每张图登记 `shotGroup`、前置状态、真实操作、后置状态和可见变化区域。
2-A. **同组截图多态硬门禁（用户反馈后强制执行）**：同一 `shotGroup` 内的截图必须来自同一条真实业务链路的不同操作节点，至少明确覆盖“前置状态 → 真实操作 → 后置状态 → 可见变化区域”；组内相邻截图的按钮高亮、表单值、筛选结果、选中对象、叠加标记、列表行、进度/成功/异常状态或三维视角必须有肉眼可辨的实质变化。只有时间、光标、轻微滚动、数字刷新、toast 消失、颜色微调或裁剪框轻微位移的图片不得组成一组，也不得写入手册；每组至少保留 2 张、建议 3–4 张互不相同的流程态图。截图采集前必须在 `shotGroups` 登记动作和变化，采集后做并排/像素差异抽检；发现同屏近似图立即回到当前运行项目重新操作补截，禁止以改文件名、复制、裁切、拼接、重采样或旧缓存冒充不同状态。
2-A.1. **同页步骤交互多态（生成期前置 + 新增硬门禁）**：这些交互不是截图期临时摆拍，而是系统生成时就要按“非静态页、操作后必有可见状态变化”写进代码；先为每个菜单按本项目业务自主编译操作链再编码。具体到采集：同一个页面或同一业务模块需要两张以上截图时，必须为每个入选截图步骤设计并实际执行一个会留下可见后果的业务操作；优先采用打开并保持可见的弹框/抽屉/详情面板，随后输入或修改字段、切换页签、筛选、选中对象、提交/审核/派发/回退/锁定/归档，再截取操作后状态。弹框不是装饰：弹框内必须承载当前业务数据或动作结果，并使至少两个可见区域（表单值、详情内容、状态标签、结果列表、按钮可用性、影像/三维联动）发生变化；“打开后立即关闭”、只换提示语或只改变光标的截图不合格。每一步的 `shotGroup` 记录 `stepId`、弹框/操作名称、前置状态、后置状态和变化区域；同页相邻图并排仍像同一张图时，回到运行项目重走操作并补截。
2-B. **图文对应硬门禁**：操作手册中的每张截图必须紧邻对应“定位 → 动作 → 反馈/结果”文字，并在图注中写明当前状态与可见变化；图注不得只写“进入态/完成态”等泛化标签。截图编号、`shotGroup`、前置状态、操作、后置状态和页面可见变化必须能从 `验收记录.md` 逐条反查，文字描述与截图不一致时整组返工。
3. 正文实际嵌入的唯一截图不得少于 30 张；数量以最终 DOCX 的独立 `ImageRun` 为准，不得用截图缓存数量、复合拼图、重复引用或同图改名凑数。建议控制在 35–50 张，且每张都对应真实页面/流程状态。
4. 高清采集规格固定为 viewport `1440×900`、`deviceScaleFactor: 2`；优先 PNG，JPEG quality ≥90；原图中的文字、按钮、状态、影像标注和三维对象必须在 100% 查看时肉眼可读。

5. 原图宽度不得低于 2400px，推荐约 `2880×1800`；禁止把 1280×720、压缩缩略图、浏览器缩放截图、模糊重采样或反复压缩图当作高清原图。尺寸、格式、文件大小和质量结论写入验收记录。
6. 每张截图必须是完整业务页面，不得只截侧栏、局部空白或失焦画面；正文嵌入保持原始比例，禁止拉伸、裁掉关键状态或再次低质量压缩。
7. 模糊、白屏、错项目、未登录、过期 UI、关键文字不可读或状态变化无法辨认时，截图门禁失败：重新启动当前项目并补截/重截对应图，不得用文字说明或旧图替代。

## 完成度锚点（交付必须达到）

### 工业诊断台级页面功能复杂度（强制）

页面“能点”不等于“够复杂”。本技能交付的业务页必须达到工业现场诊断/解析/预警工作台的功能复杂度：

1. **多区同屏**：对象/仪器树或工况列、中央解析舞台、规则/结果/风险面板同时在首屏工作，而不是先点进详情才看见内容。
2. **可切换判断**：至少有对象层级或诊断工况切换；切换后舞台、数值、规则命中与结论一起变。
3. **规则与证据在场**：有对照表、映射表、峰表、告警栈等结构化判断区，禁止只有大数字 KPI。
4. **业务语义反馈**：关键操作反馈必须写出对象、判断或处置，禁止空“操作成功”。
5. **密度抬升**：每页 ≥16 有效入口、≥5 专属动作；全站 ≥5 页达到高密度诊断台加强标准。

详细条文与反例见 [页面异构与密度门禁](references/页面异构与密度门禁.md)。

最终交付的**三维与主工作台**须达到**工业数字孪生工厂/仓储/产线**参考级观感，而不是“页面里塞了一个旋转盒子”或“虚空里一台单机”：

1. **名称驱动的主三维舞台（现场级）**：主场景须占据主要视觉权重并可旋转/缩放/平移；默认按**整厂/产线/站场/仓储/车间工段**组织，而不是单机居中。可依据名称采用仓储鸟瞰、玻璃厂房壳透视、实体车间沉浸、偏心舞台、环形站场、对角流程等独有拓扑；业务舱/HUD 必须服务现场判断。
2. **高完成度现场建模（Three.js 技能增强）**：必须按 [Three.js高级建模技能接入](references/Three.js高级建模技能接入.md) 路由 `threejs-object-sculptor` / `threejs-procedural-geometry` / `threejs-procedural-materials` 等技能，用**现场级分层程序化装配**做出可识别业务现场。主场景最低：**分区 ≥2、设备族 ≥3、命名可点选部件 ≥24、几何体 ≥48、材质 ≥6、装配层级 ≥4、业务锚点 ≥8、路径层 ≥1**。必须含地坪分区、通道、结构骨架（柱网/屋顶/墙壳）、护栏/料箱等现场构件，以及货架/输送/机台/机器人等设备集群。**禁止**单 primitive、单机悬空或无语义积木堆冒充整场。
3. **材质、光影与工业色**：PBR 分区（结构钢/设备漆/安全黄橙/地坪/玻璃/发光路径等）、环境光+主方向光（投阴影）+补光、接触阴影或 AO、边缘可读；模型必须站在地坪上。可用半透明厂房壳透视或实体车间写实，但必须像可运营现场。
4. **多视角 + 多状态 + 路径**：对齐 `threejs-camera-controls-and-rigs`；至少 **高位总览、俯视/等轴、侧视/产线透视、近景** 4 预设；同一现场至少 **4 种业务状态**可切换；工艺/物流路径可显隐或流动；切换后网格、颜色、显隐、发光、路径、标注或动画**立刻可见变化**。
5. **业务耦合与 HUD**：点击模型部位 → 侧栏详情/告警/趋势/铭牌联动；侧栏选设备 → 模型高亮/飞入分区；主孪生页 ≥3 个与模型同源浮层（KPI/告警气泡/路径图例等）；影像或图表与模型状态同源（Pinia）。
6. **名称驱动扩展环境**：按全称词根启用 2–6 个扩展 threejs 技能（建筑厂房/植被/水体/海洋/大气/粒子/运动机构等），每项必须有可见后果；工厂/车间/仓储类名称优先 buildings + motion。
7. **循环验收**：三维未达现场级硬门槛前不得宣称完成；必须按 [落地验收循环](references/落地验收循环.md)、[三维建模完成度](references/三维建模完成度.md) 与 `threejs-visual-validation` 口径多轮修到勾选通过。

细则见 [Three.js高级建模技能接入](references/Three.js高级建模技能接入.md)、[三维建模完成度](references/三维建模完成度.md)、[设计与实现约束](references/设计与实现约束.md) 与 [页面异构与密度门禁](references/页面异构与密度门禁.md)。

- **优先改造现有全栈项目**；若工作区只有前端，则在同一项目内补齐真实后端、数据层和测试，不得停留在前端原型。
- 默认技术栈：Vue、TypeScript、Vite、TailwindCSS、Pinia、Vue Router、Canvas、**Three.js（三维为默认硬依赖，不可省略；必须接入已安装 threejs-* 高级技能包口径）**，以及 FastAPI/SQLModel/SQLite 或项目现有等价后端栈。
- 前端按钮、图像处理、图表联动、任务状态和三维状态必须产生真实可见结果；核心业务状态、规则判断、保存、审核、归档和查询必须由后端 API 与持久化层提供，不能只依赖浏览器内存模拟。
- **严禁**调用生图能力（含 imagegen）。生图不能替代真实案例图。
- **真实网图案例默认启用（中国境内硬门禁）**：系统生成时必须抓取并本地化与软件全称强相关、画面地点明确属于**中国境内（默认中国大陆）**的真实网上图片作为业务案例/证据影像，细则见 [真实网图案例规范](references/真实网图案例规范.md)。除非用户明确指定某个外国国家/地区，否则禁止下载、保留、引用或交付外国场景图片。最低 **≥6 张**不同中国真实图，覆盖 ≥3 个业务页；核心链路至少 2 张中国真实原始案例图可载入处理。
- **选图与落地硬规则**：只选中国境内且与名称对象/场所/工具相关的图片；下载前必须从文件页标题、说明、地点/坐标或权威来源正文确认中国地点，不能只凭画面猜测。下载到 `public/cases/`（或统一本地目录）；代码引用本地路径；在 `public/cases/manifest.json` 与 `设计说明.md` 建立来源 URL、许可、`country: 中国`、省市/具体地点、地点依据、名称词根、使用页面、业务角色台账。素材不足时继续搜索中国图片，不得用外国图片补位。禁止无关装饰网图、禁止无台账热链当主素材、禁止断网即空白的唯一外链依赖。
- **演示素材仅作补位**：中国境内真实网图不足槽位或下载失败时，可用 Canvas/矢量/程序化纹理并标注“前端演示素材”，但整项目中国真实网图不得低于门槛；不得改用外国图片，否则素材门禁不通过。
- **图表不是基础标配**：只有当图表直接服务于名称对应的业务判断，并且能说明数据来源、判断结论和点击后的业务后果时才创建。无关趋势线、装饰性环图、假指标、图表墙和为了凑密度的 chart 一律删除，改用证据列表、状态矩阵、时间轨道、影像标注或对象明细。
- **名称—内容一致性硬门槛**：每个页面的对象、术语、影像、模型部件、操作、状态、结果和示例数据都必须能追溯到软件名称及其单点业务切口；无法通过“名称删除测试”和“行业替换测试”的内容不得保留。
- **全称显示硬门槛**：界面、手册、设计说明、README、后端服务标题与浏览器标题中的软件名称一律使用用户提供的软件全称逐字一致（中文原文直接写入，禁止 Unicode 转义写法）；不得出现任何简称、缩写或别称。
- **默认生成细致操作手册**：项目根目录必须产出 `操作手册.md`，按 [操作手册规范](references/操作手册规范.md) 与 [操作手册去AI味与研发留痕](references/操作手册去AI味与研发留痕.md) 写清页面用途、前置条件、逐步操作、输入输出、状态变化、异常与回退、数据留痕、模拟边界、去 AI 味自检与研发留痕引用；用户明确不要手册时才可省略。
- **默认生成类 GitHub 研发留痕**：项目根 `研发留痕/`（研发日志、提交记录、PR 审计、版本发布等）。生成时最少询问或使用：`软件全称` + `开发人员/团队`；著作权人有则写入、无则待登记。有真实 git 优先提取真实历史。
- **默认按完整开发者流程推进并留痕**：需求→设计→前后端编码→数据库初始化→接口联调→自测→验收→部署→文档；`操作手册.md` 必须体现开发留痕（含 PR/版本/日志摘要），角色用用户提供的开发者信息或需求/研发/测试/部署/文档等统称；禁止伪造未提供的公司/著作权人；真实开发优先，禁止虚拟图/生图/无关内容/跑不通流程。
- **手册反 AI/反模板**：禁止总结腔、元叙述、万能宣传与跨行业可替换段；必须通过换行业、同级换词、公开通用句三项检查。
- 后端、数据库、接口鉴权和真实算法不是可选增强，而是本技能的默认实现层；除非用户明确要求仅做原型，否则不得把后端留到后续阶段。


## UI 贴合标题、好看创新、登录页与多布局硬门槛（新增强化）

以下提示词是编码与验收的**硬门槛**，不是建议。未写入 `设计说明.md` 并在实现中落地前，不得批量写页面。

### A. 界面必须符合标题/软件全称
- 打开任意页面，用户应能从对象、术语、材质、场景、操作和结果判断“这就是该软件全称对应的系统”，而不是“普通管理系统 + 顶部标题”。
- 页面标题、导航名、按钮文案、空状态、告警、状态色、三维部件名、影像标注名都必须能回溯到名称中的对象/动作/场所/结果。
- **软件全称逐字显示（强制）**：系统内所有页面、登录页、顶栏、导航夹脊、浏览器标签与项目内文档中出现的软件名称，必须与用户提供的软件全称逐字一致，禁止任何简称、缩写、换词、别称、拆词重组或“××工作簿/工作平台/分析系统”替代；全称过长时可分行或竖排、缩小字号展示，但不得省略或改写任何一个字；装饰性签名元素不得使用软件名称的简写（可用图形/图标代替名称）。验收时逐页抽查名称显示，出现非全称即判定失败。
- 通过**标题一致性测试**：把软件全称改成无关名称后，当前 UI 应明显违和；若仍像通用后台，判定失败并重做视觉母题与术语。
- 禁止只把软件全称贴在顶栏/登录卡片上，而内容仍是“用户管理、数据统计、系统设置”一类可替换行业模块。

### B. 必须创新，且必须好看（强制先走 frontend-design）
- 编码前必须读取并应用 `frontend-design`：完整打开 `E:\machengji\.dsh\skills\frontend-design\SKILL.md`（若不存在则读 `E:\machengji\.dsh\skills\frontend-design\SKILL.md`），并按 [frontend-design接入](references/frontend-design接入.md) 产出视觉精修方案；未完成不得批量写页面。
- “创新”不等于乱加特效：每个视觉决定都要回答“来自名称哪个词、帮助完成哪个判断、为何比通用后台更好看更易用”。
- “好看”必须可检查：主次层级清晰、留白与密度有节奏、色彩 4–6 命名令牌克制、字体角色成对、材质与边缘统一、关键操作 contrast 足够、首屏有记忆点且不脏不乱。
- 必须在 `设计说明.md` 写出 frontend-design 方案：色板、字体角色、布局概念、签名元素、动效计划、文案口径、反 AI 默认审美自检；实现颜色/字号/签名元素只能从该方案派生。
- 每个项目至少 1 个**名称专属记忆点/签名元素**（结构隐喻、空间剖面、流程仪式、材料控制器、状态织带等），并在首页或登录页首屏可见；大胆设计只集中这一处，其余克制。
- 禁止默认暗黑霓虹、雾灰青绿万能后台、大玻璃拟态卡片墙、无意义渐变和装饰性发光数字充当“高级感”。
- 禁止为了密度把界面塞满同形卡片；好看优先服务现场判断，而不是堆控件。

### C. 登录页必须创新（功能可简，视觉不可套模板）
- 登录功能可保持账号/密码/进入系统，但**视觉、布局、业务准入语境必须创新**，且与软件全称强绑定。
- 登录页至少同时满足：
  1. 独立构图（不可直接复用“左图右表单 / 居中白卡片 / 全屏模糊背景 + 通用表单”而不改结构）；
  2. 名称对象或现场工具成为首屏主体（可用程序化三维、Canvas 结构、票据/剖面/轨道等隐喻，禁止无关网图）；
  3. 有业务准入语境：为何进入、进入后处理什么对象、失败/空状态如何用业务语言反馈；
  4. 与首页视觉母题同族，但布局骨架不同，不能登录后只是同一卡片换位置。
- 登录页必须单独写入 `设计说明.md` 的“登录页独立性记录”：构图、名称映射、记忆点、与通用模板差异、进入后落点。
- 验收时登录页与业务页同等抽查；登录页模板化 = 第一关失败。

### D. 各种布局必须多样，禁止一套骨架打天下
- 全部业务页（由信息架构族定为 9–15 个，含登录）必须使用**多种布局母版**；同一布局母版最多 2 页，且这两页仍要在视觉重心、阅读方向、工具区、结果区、模型/影像角色上明显不同。禁止为凑 15 页复制同构页。
- 必须主动组合不同布局语法，而不是微调同一网格：例如中央舞台、四角浮层、双画布比对、纵向步骤走廊、胶卷轨道、关系画布、分区地图、环形工具盘、档案墙抽屉、流程编排板等。
- 导航拓扑、主舞台位置、面板数量与面积关系、按钮密铺方式均不得在 3 页以上同时重复。
- 相邻页面至少改变 8 项异构维度中的 5 项；仅改颜色、图标、标题、CSS 网格坐标不算新布局。
- 站内全页缩略拼图缩小到 20% 且隐藏标题后，仍应靠轮廓区分职责；否则重做布局而不是补文案。第三页再出现“左树 + 中厂房/展厅孪生 + 右栈”即失败。

5. 登录页独立性记录；
6. 本案页数与布局母版清单、重复预算、近案禁用壳族；

## 跨项目差异化编译协议（固定基线 + 项目变量，强制）

本技能不追求“每次随机换皮”，而是把稳定的质量要求与每案必须重编译的变量分开。完整协议见 [跨项目差异化编译协议](references/跨项目差异化编译协议.md)，编码前必须读取并执行。

### A. 不可变基线（每案相同）

真实前后端、鉴权与持久化、中文界面、UTF-8 无 BOM、Three.js/等价三维、真实流程态截图、核心闭环、接口错误分支、研发留痕、`设计说明.md`/`验收记录.md`/`操作手册.md`、截图/WPS/页数/代码文档占比/目录清洁等硬门禁一律保留；“不一样”不能通过删减功能或降低验收标准实现。

### B. 项目变量层（每案必须重新生成）

在项目 `_soft_work/variation-manifest.json` 生成稳定的 `variationId`，推荐以 `SHA-256(软件全称|核心判断|最近指纹ID串|本案序号)` 取前 12 位，不使用不可复现的随机数；同一项目返工沿用原值。至少重新编译信息架构族、应用壳/导航、首页轮廓、页面顺序、业务对象/状态机、API/Store/文件拓扑、三维现场族、视觉材质、标志性交互、手册语法和截图状态路径；“换色/换图标/换标题”不计入差异。

### C. 差异预算与冷却

与最近 3 个最相似项目对照 12 个轴（信息架构、导航、壳拓扑、首页轮廓、页面顺序、视觉材质、字体层级、图表表达、三维现场族、标志性交互、后端拓扑、状态机），每个近案至少 **8/12 轴不同**，且首页轮廓、三维现场族、后端拓扑、状态机至少命中 3 轴。近案少于 3 个时对照全部可用案例，并把本案选择写入基准台账供后续冷却。最近 3 案用过的壳族、信息架构族、三维现场族进入冷却；确需复用必须在编译单写豁免理由。原子按钮/图表容器/错误处理骨架可以复用，页面级组合、领域模型、路由树、状态枚举和后端目录不能整组复用。

### D. 编译单与证据

`variation-manifest.json` 至少包含 `invariants`、`selected`、`forbiddenFromRecentCases`、`reuseLedger`、`differenceScore` 和 `evidence`。`设计说明.md` 摘要选择结果、淘汰方案、近案禁用项和 12 轴证据；`验收记录.md` 勾选名称删除、行业替换、近案同构三项测试。软著整理时把编译单移入 `[软件全称]-源代码/研发留痕/` 或备份目录，不把 `_soft_work` 留在最终根目录。

### E. 失败判定

首页缩略图、路由/后端目录树、核心状态机或手册预留结构若仅有名词/颜色/文件前缀变化，直接判定“换词项目”，退回名称编译阶段；不得先生成文档再用文案掩盖同构。

## 名称驱动的 UI 创新硬门槛（禁止每次一样）

把软件全称当作“界面生成约束”，而不是标题占位符。必须先完成名称到界面的编译，再开始编码：

1. **拆解名称语义**：提取核心对象、关键动作、真实场所、判断结果、主要使用者和现场工具，并逐项映射到空间拓扑、导航方式、组件几何、材质光线、数据表达和交互节奏。映射不完整时不得进入批量页面实现。
2. **三案竞争后选型**：编码前必须提出三套来源不同的候选方向——对象/结构隐喻、流程/时间隐喻、场所/工具隐喻；按名称贴合度、现场判断效率、三维可表现性和跨项目新颖度评分，选出一套并记录另外两套被淘汰的原因。禁止直接采用上一个项目的视觉方向。
3. **frontend-design 视觉精修（强制）**：在胜出案上读取并应用 `frontend-design`，产出可执行视觉方案——4–6 命名色、字体角色配对、布局概念与 ASCII 线框、唯一签名元素、动效取舍、中文文案口径、反 AI 默认审美自检。细则见 [frontend-design接入](references/frontend-design接入.md)。未完成精修不得进入指纹定稿与编码。
3-B. **Three.js 高级建模路由（强制）**：读取 `threejs-choose-skills` 与基线/扩展 `threejs-*` 技能，在 `设计说明.md` 写路由表、装配层级、材质令牌与验证计划；未完成不得进入主模型工厂编码。细则见 [Three.js高级建模技能接入](references/Three.js高级建模技能接入.md)。
4. **建立 UI 创新指纹**：在 `设计说明.md` 记录视觉母题、frontend-design 色板与字体、几何与边界语言、表面材质、导航拓扑、页面布局语法、图表语言、动效节奏、三维舞台形状和唯一标志性交互；每项都要标注它来自名称中的哪个词、服务哪个判断，并额外写明“为何好看、如何避免通用后台感/AI 默认脸”。对每个图表额外记录“数据来源—业务判断—点击后果”，对每张外部素材记录来源与授权；没有这两项记录就不使用。
5. **禁止预设外壳**：不得默认使用“固定宽度左栏 + 顶栏 + 多块同形卡片 + 中央深色模型框”，也不得因为技术方便而让所有项目共享同一应用壳。导航可以是流程脊柱、票据折页、空间罗盘、分层工具架、顶部舱轨、时间刻度带或全屏现场模式，但必须由名称和现场任务解释。
6. **禁止单一通用页面生成器**：不得让全部业务路由通过同一个通用页面组件、同一组固定面板和一份配置数组渲染，仅交换标题、数据、网格坐标或模型名称。允许复用按钮、图表、面板等原子组件；页面级组合、主要结构和信息顺序必须按职责独立实现。同一主体骨架最多用于两个强相关页面，且二者仍须改变至少五个异构维度。
7. **设置页面重复预算**：本案实际页面中，同一导航内容排列、同一主舞台位置、同一面板数量与面积关系、同一按钮密铺方式均不得在三页以上同时重复；三维舞台位于同一屏幕区域的页面不得超过总页数三分之一。公共品牌区可复用，公共壳不得吞掉页面主体。
8. **跨项目防重复**：工作区存在同级案例时，编码前抽查最近或最相似的 3–5 个项目，记录不可复用项；本项目至少在导航拓扑、首页轮廓、色彩材质、字体层级、组件几何、模型舞台形状、图表表达、按钮分布、背景纹理和标志性交互十项中的七项明显不同。若最近两个项目都使用同类导航或首页舞台，本项目必须更换该维度。图表表达只有在名称和判断需要时才参与比较，不得为了满足差异强行添加图表。
9. **页面轮廓唯一**：本案实际业务页面必须有职责驱动的主体骨架；相邻页面至少改变视觉重心、阅读方向、组件骨架、信息层级、模型/影像角色、工具位置、动作密铺和结果位置八项中的五项。仅交换 CSS 网格坐标、卡片顺序、颜色或图标不算新布局。
9. **创新必须可解释且不可随机应付**：每个大胆选择都要回答“来自名称中的哪个对象或动作、帮助完成哪个判断”；随机换色、随机圆角、随机卡片排布不算创新，无法解释的装饰性特效应删除。
10. **保留名称专属记忆点**：每个项目必须实现一个其他案例没有的标志性视觉或交互，例如名称对象驱动的时间刻度、空间剖面、证据脊柱、状态织带、材料化控制器或现场操作仪式；不得把发光大数字、渐变卡片和普通玻璃拟态当作创新。
11. **双重缩略验收**：截取全部业务页面的同尺寸全页截图，生成站内缩略拼图；再把首页与 3–5 个同级案例首页并排生成跨项目对照。缩小到 20% 后若有三页以上同轮廓、首页只能靠标题区分、或与邻近案例高度相似，本轮直接不通过并重做布局。
12. **登录页单列创新门禁**：登录页必须有名称专属构图、业务准入语境和首屏记忆点；功能可只做账号密码，但视觉与布局不得套用通用登录模板，且须与首页骨架不同。
13. **标题贴合门禁**：所有页面通过“换标题即违和”测试；对象、操作、状态、模型部件和示例数据必须服务软件全称，而不是服务通用后台。
14. **好看可检门禁（含 frontend-design）**：主次层级、色板 token、字体配对、材质统一、对比度、签名元素与反 AI 默认脸证据都可指出；乱堆卡片、脏色、无意义特效、模板脸、未派生自设计说明的临时风格一律返工。

详细编译方法与量化门槛见 [设计与实现约束](references/设计与实现约束.md)、[跨项目异构与反流水线](references/跨项目异构与反流水线.md) 与 [页面异构与密度门禁](references/页面异构与密度门禁.md)。

## 通用质量门禁（所有垂直系统必须执行）

以下要求不是当前项目特例，而是本技能生成任何垂直业务系统时的通用硬门槛：

1. **页面异构与视觉原创**：每个业务菜单必须使用职责驱动的独立主体骨架；相邻页面至少在主要视觉重心、阅读方向、组件排列、信息结构、图像/模型角色、工具位置、按钮密铺逻辑、结果面板位置中改变5项。禁止复制“标题＋三维卡片＋右侧详情”后只改文案，禁止把同一套CSS网格换坐标冒充创新。
2. **交互密度与功能复杂度**：按页职责配额，禁止每页都做成同一张工业诊断台。主判断页（全站 2–4 页）有效入口 ≥14、专属动作 ≥5，允许高密度；工序/文书页 8–14 个入口即可；现场/模型页以状态肉眼可辨为准。动作必须真实改变状态、视图、模型、影像、工况、任务、筛选、流程或留痕，并给出含对象/判断/处置语义的反馈。全站至少 3 页高密度。禁止用“刷新/导出/同步孪生/计数”凑入口。细则见 [页面异构与密度门禁](references/页面异构与密度门禁.md) 与 [跨项目异构与反流水线](references/跨项目异构与反流水线.md)。
3. **单点纵深**：从系统全称推导唯一现场判断，所有菜单和子功能围绕同一判断深入，形成输入→处理→定位→处置/重放→对照→复查→归档闭环；禁止泛化为普通后台。
4. **三维分化**：至少 3 套结构明显不同的三维模型；主页模型复杂度、部件层级、环境参照和交互密度必须最高；不同页面不能只换颜色或视角。
5. **验证先行**：编码前建立三套候选视觉方向及评分、**frontend-design 视觉精修方案**、UI创新指纹、名称语义映射表、同级案例防重复表、逐页异构矩阵、页面重复预算、操作密度表和单点业务链路表；验收时生成站内全页缩略拼图与跨项目首页对照，并逐页或至少抽查5页，记录布局、信息结构、按钮数量、专属动作、模型/影像角色、token 一致性和真实状态后果。只做构建检查不算通过。
