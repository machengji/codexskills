# 落地验收循环

在 ZCode 内交付垂直影像系统时使用。目标：用可复现步骤证明系统可运行、可交互、**三维达到 Three.js 高级技能包加持的工业现场级数字孪生完成度**（整厂/产线/仓储观感，而非单机玩具）、业务垂直且达标，而不是“代码看起来很多”；同时证明 `操作手册.md` 去 AI 味/非模板，且 `研发留痕/` 类 GitHub 辅助材料齐全可引用。

## 一、第一步前置门禁与何时进入本循环

### 0. 先做名称编译与自主创新审查

在首轮编码前，必须完成并审查 `设计说明.md`：三案评分与淘汰理由、**frontend-design 视觉精修方案**、名称语义映射、UI创新指纹、登录页独立性记录、逐页异构矩阵、页面重复预算、同级案例十维差异、操作密度与功能复杂度表和单点业务链路。必须已读取 `frontend-design` 技能或按 [frontend-design接入](frontend-design接入.md) 降级执行并记录。至少做两轮前置设计复核；任一项失败，不能开始批量页面实现。

登录页、首页和每个业务页都必须有自己的职责、主体轮廓、阅读方向、按钮密铺方式和专属动作。只改标题、颜色、数字、图标或CSS坐标不算自主创新。


- 首轮页面与核心链路（**含主三维舞台**）已落盘后立刻进入；
- 每次修复后重新进入；
- 用户要求“反复验证 / 验收到达标 / 高度完成 3D”时，**至少完整跑 3 轮**（含三维门禁）；
- 一般交付也不得少于 **3 轮**，且没有固定最大轮次；未全绿就继续循环。

## 二、推荐命令序（按项目包管理器调整）

在项目根目录：

```bash
npm install
npm run build
npm run dev
```

构建失败、类型错误、启动即崩：先修工程问题，再谈业务与三维验收。

可选静态检索（在项目源码目录执行，按实际栈调整路径）：

```bash
# 路由/页面规模粗检
rg -n "path:|name:|component:" src/router src/views src/pages || true

# 禁止残留与英文界面粗检（按仓库习惯收紧）
rg -n "TODO|FIXME|placeholder|lorem|Coming soon" src || true
rg -n "\b(Login|Dashboard|Submit|Cancel|Admin)\b" src --glob '!**/node_modules/**' || true

# 单一页面生成器与固定外壳风险粗检；命中后必须人工确认页面级结构是否独立
rg -n "pages\.map|pageByPath|PlatformView|GenericPage|layoutConfig|panelConfig" src || true
rg -n "grid-template-areas|sidebar|topbar|dashboard-card" src --glob '*.{vue,tsx,jsx,css,scss}' || true

# 三维依赖与低完成度风险粗检
rg -n "from 'three'|from \"three\"|three/" src || true
rg -n "BoxGeometry|SphereGeometry|CylinderGeometry|Group|MeshStandardMaterial|MeshPhysicalMaterial" src || true
rg -n "cameraPreset|modelStatus|applyModelState|InstancedMesh|castShadow|receiveShadow" src || true
rg -n "Three.js 技能路由|threejs-object-sculptor|threejs-procedural-geometry|threejs-procedural-materials" 设计说明.md || true
```

发现命中 TODO、假按钮、无 three 引用、仅单个 BoxGeometry 且无 Group 组合、无 castShadow/接地、设计说明缺少 Three.js 技能路由：记入缺口清单并修复，不要忽略。单一页面生成器或固定外壳检索命中不一定直接失败，但必须检查是否用同一组件树和固定面板清单承载全部路由；若是，则直接判定 UI 门禁失败。

## 四、推荐轮次节奏（三维交付）

| 轮次 | 焦点 |

每轮结束必须更新项目内 `验收记录.md`。三维门禁（清单 E）未全绿，禁止写“已达标”。

## 五、缺口清单格式（修复时只用这个）

每轮验收结束写入项目内 `验收记录.md`（可追加），格式：

```text
## 第 N 轮
时间：
构建：通过/失败（摘要）
三维门禁：通过项/失败项
缺口：
1. [页面或模块] 问题 — 复现 — 拟修
2. ...
本轮已修：
1. ...
复验结果：
```

下一轮**只优先修清单项**，避免无目标重写整站。三维缺口优先于装饰性 UI 微调。

## 六、达标判定

同时满足：

1. 清单 A–H 无未勾选项（三维门禁 E、素材 G、图表与手册 H 不可豁免）；
2. 最近一次 `build` 成功；
3. 核心业务链路在界面上可完整走通一次（从进入案例到复查/归档有状态变化）；
4. 主三维场景可演示：现场级分层模型（分区/设备族/路径/骨架）、旋转缩放、阴影接地、状态切换、高位总览等视角切换、部件/HUD 联动；Three.js 技能路由表齐全；
5. 三案选型、frontend-design 精修、名称语义映射、UI创新指纹、单一页面生成器禁用、页面重复预算、同级案例十维差异和双重缩略对照门禁全部通过；
6. 至少完成前置设计审查轮次和3轮完整运行/行为/视觉验收；没有固定最大轮次，最后一轮必须清单全绿，不以“无新增缺口”替代“全部通过”。

未达标时：继续修，**不要**用“后续可优化”搪塞关键项（页面数、假按钮、构建失败、无影像处理、低完成度三维/单机虚空、无分区无路径、无状态/无多视角、无 HUD 同源、英文界面、全局滚动、单一通用页面壳、页面轮廓重复或跨项目首页雷同）。
