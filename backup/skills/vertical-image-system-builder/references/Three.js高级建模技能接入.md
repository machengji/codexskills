## 二、默认基线技能（每个项目强制）

无论行业，主三维舞台至少启用下列技能口径：

| 技能目录 | 强制用途 |
| --- | --- |
| `threejs-choose-skills` | 多系统场景路由，选最小因果技能集 |
| `threejs-procedural-geometry` | 索引网格、组合扫掠、批处理、动态更新、轮廓线 |
| `threejs-procedural-materials` | 程序化 PBR、粗糙度/金属度分区、实例变体 |
| `threejs-object-sculptor` | 参考图/名称对象的程序化重建计划与分层装配 |
| `threejs-camera-controls-and-rigs` | 相机主权、预设、聚焦飞入、大坐标稳定 |
| `threejs-scalable-real-time-shadows` | 可读实时阴影/接触阴影，避免“漂浮模型” |
| `threejs-ambient-contact-shading` | AO/接触暗部、结构缝可读性 |
| `threejs-image-pipeline` | 帧图管线最小闭环，最终输出可控 |
| `threejs-visual-validation` | 截图/状态/性能/生命周期可证伪验收 |
| `threejs-debugging` | 黑屏、报错、版本坑的定位与遏制 |

可选但推荐（名称含大型场景/大气时优先）：

- `threejs-exposure-color-grading`：曝光与色调映射，避免过曝死白或死黑
- `threejs-bloom`：仅当名称对象确有高亮光源/告警灯/焊弧等，禁止默认霓虹泛滥
- `threejs-compatibility-fallbacks`：WebGPU 不可用时的降级声明

## 四、高级真实建模硬门槛（高于旧版）

旧版“≥8 部件 / ≥12 几何 / ≥3 材质”和中期“≥16/≥28/≥5”都只是历史底线；
当前对标工业数字孪生工厂/仓储/产线参考图后，**主场景**必须按**现场级**默认抬升为：

| 项 | 新最低要求 |
| --- | --- |
| 场景类型 | **现场级数字孪生**（整厂/产线/站场/仓储/车间），禁止主场景单机悬空 |
| 功能分区 | ≥ **2** |
| 设备/构筑物族 | ≥ **3** |
| 命名可点选部件（Group/Mesh） | ≥ **24** |
| 几何体实例（可复用/实例化） | ≥ **48** |
| 材质种类（PBR 参数可区分） | ≥ **6**（结构钢、设备漆、安全黄/橙、地坪、玻璃/灯罩、发光指示/路径 等可区分） |
| 装配层级 | ≥ **4 层**：场地环境 → 分区/产线 → 设备主机 → 连接件/线槽/护栏/指示 |
| 业务锚点 | ≥ **8**（可高亮故障/工位/测点/分区） |
| 工艺/物流路径层 | ≥ **1** 条可见路径（输送/管廊/巡检/AGV/流线，可动画） |
| 环境参照 | 地坪分区 + 柱网/屋顶/墙壳至少一类；护栏/料箱/人物尺度；必须有接触阴影或等效接地 |
| 灯光 | 环境光 + 主方向光 + 补光/轮廓光；主光投射阴影；车间感暖白主光优先 |
| 边缘可读 | Edges/轮廓/AO/材质对比至少两种手段 |
| HUD 叠层 | 主孪生页 ≥ **3** 个与模型同源浮层（铭牌/KPI/告警/图例） |
| 细节层 | 近景页额外 ≥ **2 类** 微结构（螺栓阵列简化、面板缝、线槽、铭牌条、护罩格栅等） |

真实感判定（任一失败即三维不达标）：

1. **现场可识别性**：缩略图 20% 仍能看出名称对应的整厂/产线/站场/仓储现场，不是无语义积木堆或单机虚空。
2. **分区与路径**：至少 2 个分区 + 1 条工艺/物流路径层；通道关系清楚。
3. **结构合理性**：有地坪、支撑、连接、厚度暗示；禁止部件悬空无交接。
4. **多设备族**：至少 3 类职责不同的设备/构筑物外形可区分。
5. **材质分区**：不同功能区 roughness/metalness/color 可分，工业色语义成立，不是同一灰材质刷全场。
6. **光影体积感**：有受光面/背光面/接触暗部；禁止全平光塑料感。
7. **业务可读**：状态切换改变颜色/发光/显隐/运动/路径，1 秒内可见。
8. **非玩具感**：禁止“1 个 Box + 1 个 Cylinder + 单色 StandardMaterial”充当整机或整场。
9. **HUD 同源**：主孪生页浮层信息与选中设备/分区状态同源，不是纯装饰贴纸。

## 五、实现顺序（代理必须遵守）

1. **现场总图计划**（`threejs-object-sculptor`）  
   先写整场拆解：分区轴线、主通道、地坪、柱网/屋顶/墙壳、设备族、路径层、HUD 锚点；再写单机关节。
2. **几何工厂**（`threejs-procedural-geometry`）  
   `createSiteTwin(): THREE.Group`，命名树完整；货架/护栏/托盘/重复工位优先实例化。
3. **材质图谱**（`threejs-procedural-materials`）  
   建立 `materials.ts` 工业色令牌：结构钢、设备漆、安全黄/橙、地坪、玻璃壳、路径发光、告警发射等。
4. **装配与锚点**  
   分区 Group → 设备 → 连接件/走线/护栏/地脚；`userData.partId/zoneId/label/statusKeys`。
5. **灯光阴影与接触**（shadows + ambient-contact）  
   先让整场“站在地坪上”，再加花活。
6. **相机预设与飞入**（camera-controls-and-rigs）  
   ≥4 预设（默认高位总览）+ focusPart + flyToZone。
7. **状态机与路径层**  
   ≥4 业务状态；`applyModelState` 统一改设备/路径/标牌；路径可流动动画。
8. **HUD 同源叠层**  
   铭牌/KPI/告警气泡与 Pinia 选中态同步，至少 3 个。
9. **名称扩展环境**  
   仅落地路由表中的建筑壳/粒子/大气/运动等，且服务现场可读。
10. **视觉验证**（`threejs-visual-validation`）  
   至少验证：首屏非空现场总览、状态切换前后差异、路径显隐、相机切换、点选高亮、无致命控制台错误。

技术偏好（与 threejs skills 对齐，但以可运行交付为准）：

- 优先现代 Three.js 写法；若工程已是 WebGLRenderer，可先稳定交付，再在不破坏业务的前提下演进。
- 禁止用过时空壳 API 冒充完成；黑屏必须走 `threejs-debugging`。
- 资源释放：卸载 dispose 几何/材质/渲染器/控件。

## 七、与页面系统的耦合

- ≥5 个三维职责页仍必需，且主页复杂度最高。
- 点选部件 ↔ 侧栏/告警/趋势必须打通。
- 真实网图案例负责“现场证据”；Three.js 负责“结构与状态孪生”。二者互补，禁止用网图静态贴图假冒可交互整机。
- 登录页可用简化程序化三维作为名称对象记忆点，但不得比主工作台更复杂却无业务状态。

## 八、失败即回退

出现下列任一情况，回到本规范与 [三维建模完成度](三维建模完成度.md) 重修，不得宣称完成：

- 未读 `threejs-choose-skills` / 未写路由表
- 主场景低于现场级新最低规格（含分区/设备族/路径/部件≥24/几何≥48）
- 仍是单 primitive、单机虚空或无层级命名树
- 无阴影/无接地/全平光
- 扩展特效与名称无关（霓虹 bloom、无端宇宙黑洞等）
- 无状态可见变化、无路径层、无 HUD 同源或无业务联动
- `threejs-visual-validation` 口径下的基础断言未做
