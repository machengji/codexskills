# 页面异构、单点纵深与交互密度门禁

本门禁适用于所有由垂直影像系统生成技能创建或改造的前端项目。它与三维门禁同等重要；构建通过不代表本门禁通过。除站内页面异构外，还必须防止不同项目之间反复生成相同UI外壳。

## 一、页面异构门禁

### 1. 先做UI创新指纹、跨项目审计和页面矩阵，再写页面

**第一步硬规则**：登录页、首页和每个业务页都要单独填写矩阵行并通过“名称删除测试、行业替换测试、模板替换测试、标题一致性测试、好看可检测试”。任何页面只靠标题、数字、颜色、图标或网格坐标变化，均判定为模板复用；登录页套用通用模板或全站同骨架，必须回退到三案设计重新选型。

编码前必须为每个菜单建立矩阵，至少记录：

- 页面职责
- 核心判断
- 布局母版
- 阅读方向
- 组件骨架
- 图像或画布角色
- 三维模型角色
- 工具带位置
- 结果面板位置
- 页面专属操作
- 图表是否必要、图表对应的名称词根与业务判断
- 影像/图片来源、授权状态与名称关联

编码前先生成对象/结构、流程/时间、场所/工具三套候选视觉方向，记录四项评分与淘汰理由；**再强制读取并应用 frontend-design**（见 [frontend-design接入](frontend-design接入.md)），产出色板 4–6、字体角色、布局概念、签名元素、动效与反默认审美自检；然后建立系统级UI创新指纹，记录名称语义映射、视觉母题、frontend-design 色/字 token、组件几何、导航拓扑、布局语法、图表语言、动效节奏、三维舞台和标志性交互。工作区有同级案例时抽查3–5个项目，写出十维差异；少于七项明显不同，或缺少 frontend-design 方案，直接不通过。

禁止先复制通用页面再只改标题、数字、颜色或少量按钮；禁止复用上一个项目的固定左栏、顶栏、六面板网格、统一圆角和配色；禁止十五个路由共用一个页面级生成器与固定面板清单，仅靠配置数组切换内容。

### 内容、图表与真实网图硬门禁

- 每页必须写明名称词根、业务对象、现场判断、页面动作和结果变化；标题、字段、示例数据、模型部件、影像标注和状态不能脱离该映射。
- 执行名称删除测试和行业替换测试：删除名称后仍能识别对象与判断；换成其他行业后不能原样复用。
- chart 不是必选组件；只有存在明确判断问题时才允许使用。每个 chart 必须有数据来源、判断结论、联动对象和点击后果，缺一项即删除。
- **中国境内真实网图案例强制启用**：按 [真实网图案例规范](真实网图案例规范.md) 下载本地化 ≥6 张地点明确属于中国境内的名称相关真实图；登记来源 URL、许可、`country: 中国`、省市地点、地点依据、页面与业务角色；除非用户明确指定外国地点，否则外国场景图片必须为 0。禁止无关装饰网图、外国图补位、无台账热链主依赖和生图。
- 不得用通用指标、无来源数据、无关图片或“看起来专业”的 chart 填充页面。

### 2. 相邻页面至少改变五项

任意相邻业务页面之间，至少改变以下八项中的五项：

1. 主要视觉重心；
2. 阅读方向，例如横向时间轴、纵向时间走廊、左右双画布、流程画布、矩阵、拼贴、泳道或三栏工作台；
3. 组件排列；
4. 信息层级；
5. 图像、画布或三维模型的业务角色；
6. 工具栏、筛选器、按钮带的位置；
7. 按钮密铺逻辑，例如左侧仪器带、底部动作带、卡片内动作、浮动控制盘、节点编辑按钮；
8. 结果、详情、证据或复查面板的位置。

不得出现多个页面长期复用“标题 + 三维卡片 + 右侧详情 + 底部按钮”骨架；仅交换CSS网格坐标、颜色或卡片顺序不算新布局。十五个页面必须形成十五个职责驱动的主体轮廓。


### 3. 页面重复预算与共享边界

- 同一主体骨架最多覆盖两个强相关页面；第三次出现即判定重复。
- 同一导航内容排列、同一主舞台位置、同一面板数量与面积关系、同一按钮密铺方式，均不得在三页以上同时重复。
- 三维舞台固定在同一屏幕区域的页面不得超过业务页总数三分之一；其余三维页应使用近景嵌入、剖切走廊、全屏现场、时间回放、地图锚点或方案预演等职责化位置。
- 公共壳只允许承载品牌、当前任务和必要全局状态；主体内容的页面级组合必须独立。允许复用原子组件，不允许复用完整页面骨架。
- 若所有路由都导向同一个页面组件，必须证明至少十三个页面拥有不同的结构化插槽树和主要组件顺序；否则直接不通过。优先为不同职责建立独立页面组件。
- 隐藏页面标题后，仍应从轮廓、工具位置、模型/影像角色与阅读方向识别页面；否则不算异构。

### 4. 名称一致性门禁

逐页检查“名称词根 → 视觉/交互后果”：

- 核心对象至少影响舞台形状、组件几何或图表标记之一；
- 关键动作至少影响导航顺序、阅读方向或动效节奏之一；
- 真实场所至少影响材质、光线、密度或空间参照之一；
- 判断结果至少影响状态色、证据表达或结果面板之一；
- 使用者与工具至少影响信息层级、控制器形式或按钮语法之一。

任何页面若无法说明名称依据，视为通用后台残留，必须重做。

### 5. 三维模型必须与页面职责绑定

- 主页模型最复杂、层级最多、环境参照最完整、交互密度最高；
- 至少三套三维模型在几何结构、部件命名、材质布局或业务锚点上明显不同；
- 三维模型变体不能只是换颜色或旋转角度；
- 页面切换后模型标题、部件统计、场景标签和工具必须同步变化。


### 6. 跨项目防重复门禁

存在同级案例时，对本项目与最近或最相似的3–5个项目执行十维比较：

1. 导航拓扑；
2. 首页主体轮廓；
3. 色彩和材质；
4. 字体层级；
5. 组件几何与圆角；
6. 三维舞台形状与位置；
7. 图表表达；
8. 按钮和工具分布；
9. 背景纹理与光线；
10. 标志性交互。

至少七项必须明显不同。禁止复制旧项目的整段CSS、页面配置数组或通用面板骨架后仅替换业务文案。

### 7. 缩略拼图与轮廓门禁

- 为全部业务页面生成同尺寸全页截图和站内缩略拼图；另生成本项目首页与3–5个同级案例首页的并排对照；不得只截5页替代全站轮廓检查。
- 隐藏标题并缩小到20%观察时，各页的主体重心、阅读方向和主要形状仍应可区分，本项目首页也应能与同级案例区分。
- 三页以上呈现相同骨架、首页与同级案例高度相似、或只能靠标题识别页面时，本轮直接不通过。
- 将拼图路径、重复风险和修复结论写入 `验收记录.md`。

## 二、单点纵深门禁

系统必须从全称推导一个不能泛化的现场判断，并围绕该判断纵向展开：

```text
现场输入
→ 采集/载入
→ 影像或波形处理
→ 重点区域/异常定位
→ 三维部件或结构映射
→ 场景、负载或处置重放
→ 前后变化对照
→ 人工判断与复查
→ 证据包归档
```

每个菜单都必须落在这条链路的不同节点上。菜单可以丰富，但不能横向扩展成无关的通用管理功能。

判断项目是否垂直时，执行替换测试：把系统名称换成其他行业，如果页面名称、模型部件、影像角色、按钮动作、数据结构和闭环仍能原样复用，则判定业务切入不够深，必须重新收紧术语和流程。

## 三、交互密度与功能复杂度门禁（工业诊断台级）

> **复杂度锚点**：生成页面的功能复杂度必须达到工业现场“诊断/解析/预警工作台”级别，而不是普通后台卡片页加几个按钮。
> 对标形态（只作复杂度参照，不要求复制其行业外壳或视觉皮肤）：多区同屏工作台、对象树/仪器列、中央解析舞台、右侧工况/规则/风险面板、顶部连续业务指标条、底部专业模块轨、可切换诊断工况、规则表与结果表并存、操作后出现带业务语义的成功/告警反馈。
> 判定口诀：**一眼像能干活的专业解析台，而不是能点击的展示页。**

### 1. 数量要求（下限，不是目标）

每个业务页面：

- 页面级与卡片级可见操作入口合计不少于 **16** 个（历史下限 12 已抬升）；
- 至少 **5** 个页面专属动作（历史下限 3 已抬升）；
- 至少 2 个操作改变主视觉、模型、波形/影像或中央解析舞台；
- 至少 2 个操作改变数据、筛选、工况、阈值、流程或规则计算结果；
- 至少 1 个操作写入操作留痕、复查节点、告警确认或成果状态；
- 至少 1 个操作打开详情/规则/证据，并与当前选中对象同源。

仅把同一动作重复摆放、无状态变化的“假按钮”、纯颜色闪烁、空提示框，**不计入**数量。

### 2. 功能复杂度结构要求（每页必须同时满足）

每个业务页面首屏（无需二次跳转）必须同时具备：

1. **不少于 3 个并发工作区**（例如：对象/仪器树或工况列 + 中央解析舞台 + 结果/规则/风险面板）。只放“大卡片墙”或“单表+侧栏”视为复杂度不足。
2. **一条业务对象层级或工况切换器**（树、多级列表、诊断工况钮阵、通道/间隔选择等），点选后必须同步改变中央舞台与右侧结果，不能只改高亮样式。
3. **一组领域规则/对照/结果表**或等价结构化判断区（≥6 行有效业务行，或 ≥4 个可切换工况且每个工况有可见结果差异）。禁止只有 KPI 数字没有判断依据。
4. **中央主解析区**占页面主视觉权重，承载三维/波形/影像/三角图/矩阵等与本页职责直接相关的解析对象；不能把主区做成装饰插画。
5. **操作反馈有业务语义**：关键操作后出现成功/告警/实景结论等反馈，文案必须包含对象、判断或处置建议，禁止“操作成功”空话。

全站至少 **5** 个业务页达到“高密度诊断台”加强标准（在上述基础上再加一项）：

- 顶栏或页内连续业务指标条（≥6 个名称相关监测值/状态码）；或
- 左侧多层对象树（≥2 级、≥8 个可点节点）+ 右侧风险/实景结论卡；或
- 多诊断工况钮阵（≥5 个）与规则映射表左右对照，切换工况后比值/着色/结论同时变化。

### 3. 什么算有效操作

有效操作必须产生真实可见后果，例如：

- 切换模型状态、视角、部件显隐、剖切、热区或间隔着色；
- 改变采样窗口、波形游标、通道筛选、阈值、诊断工况或时间范围；
- 选中对象树节点后，同步刷新舞台、表头、风险结论与留痕；
- 新增、编辑、确认、升级、退回异常事件或复查节点；
- 移动负载序列、流程节点、观察点或判定条件；
- 选择基线/处置后快照并改变对照结果；
- 生成、保存、回退、导出、归档或留痕；
- 打开与当前页面职责直接相关的详情、规则抽屉、证据或检查器。

### 4. 反例（直接判功能复杂度不合格）

- 大面积留白 + 少量卡片 + 底部一排通用按钮凑数；
- 只有“查询/重置/导出”三类通用动作，没有页面专属解析动作；
- 中央是静态图或低互动装饰模型，侧栏只读、不可改判断；
- 表格只有 2–3 行示范数据，无规则/工况/对照；
- 十五页都是“左列表右详情”或“上统计下表格”同一功能深度；
- 用 16 个无后果按钮堆密度，主区仍像展示海报。

### 5. 页面密铺方式必须变化

至少轮换使用以下方式，不得整站统一：

- 左侧仪器/对象树 + 中央场站/波形舞台 + 右侧实景风险；
- 工况钮阵 + 中央诊断图 + 规则映射表；
- 横向波形工具带 + 峰表 + 阈值条；
- 筛选器 + 中央舞台 + 右侧异常堆栈；
- 序列步骤列 + 中央时间盘 + 当前步骤检查器；
- 左右双快照 + 中央差异脊柱；
- 标签盘 + 影像标注画布 + 证据抽屉；
- 档案身份卡 + 层级栈 + 版本列；
- 寄存器/规则表格 + 影响模型 + 位域/条件检查；
- 供电路径/管廊 + 域状态卡 + 事件带；
- 动作块库 + 时间泳道 + 属性检查器；
- 流程编排画布 + 节点参数板；
- 纵向时间走廊 + 复查卡片；
- 证据包拼贴 + 封存表单；
- 时间筛选 + 中央账本 + 状态变化轨道；
- 多站/多对象矩阵比对 + 差异高亮 + 下钻。

## 四、反复验证记录

每轮都要先复核前置设计证据，再复核实现结果。没有 `设计说明.md` 与 `验收记录.md` 的前置审查记录，本轮直接不通过。登录页也必须纳入抽查，不得只抽业务页面。

每轮验收必须逐页或抽样至少五页，记录：

```text
页面：
页面职责：
布局母版：
阅读方向：
三维/影像角色：
并发工作区数与名称：
对象树/工况器：
规则或结果表行数/工况数：
可见操作入口数：
页面专属操作数：
是否达到高密度诊断台加强标准：
名称词根与视觉/交互映射：
是否触发页面重复预算：
组件排列与相邻页面的差异：
信息结构与相邻页面的差异：
按钮密铺逻辑：
真实状态后果与业务语义反馈：
垂直业务链路节点：
结论：通过/不通过
```

出现以下任一情况，本轮直接不通过：

- 页面看起来基本一样，或十五页缩略拼图中出现三页以上同骨架；
- 未完成三案竞争、frontend-design 精修与名称语义映射，或与同级案例十维差异少于七项；
- 仍使用无业务理由的固定左栏、顶栏和通用卡片外壳，或全部路由由单一页面生成器和固定面板清单承载；
- 操作入口不足 16 个；
- 页面专属操作不足 5 个；
- 并发工作区不足 3 个，或缺少对象树/工况器、规则表、主解析区之一；
- 关键操作无业务语义反馈，或全站达到“高密度诊断台”加强标准的页面少于 5 个；
- 模型只换颜色或视角；
- 菜单、字段、模型、影像和示例数据与系统名称无关；
- chart 没有明确判断用途、数据来源或点击后果；
- 中国境内真实网图案例不足门槛、未本地化、无中国地点依据台账，或存在外国场景图片、无关装饰网图/未说明授权图片；
- 操作没有真实后果或没有写入留痕；
- 违反页面重复预算，或只做了构建检查，没有做逐页面结构检查。

## 登录页、标题贴合与好看验收（强制）

### 登录页
- [ ] 登录页有独立构图，不是通用左右分栏/居中白卡片换肤
- [ ] 首屏可见名称对象或现场工具隐喻（程序化三维/Canvas/材料面板均可）
- [ ] 有业务准入语境与业务化失败反馈
- [ ] 与首页骨架不同，进入后落点明确
- [ ] 已写入登录页独立性记录

### 标题贴合
- [ ] 页面对象、术语、操作、状态、模型部件都能回溯软件全称
- [ ] 标题一致性测试通过：换无关名称后界面明显违和
- [ ] 无“用户管理/系统设置/数据统计”等可替换行业空模块充数

### 好看与多布局（含 frontend-design）
- [ ] 已读取 frontend-design 并写入视觉精修方案
