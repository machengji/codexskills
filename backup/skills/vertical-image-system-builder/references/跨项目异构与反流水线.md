# 跨项目异构与反流水线（强制）

> 目标：每次新生成的系统，肉眼和源码对照都不能看成“换了行业词的同一套”。  
> 本文件覆盖 `vertical-image-system-builder` 的编码门禁；下游软著手册必须继承这里选出的壳族、叙事族和禁止复用项。

工作区最近两个完整垂直系统（2026-08-12 / 2026-08-13）已经证明：只换色板、路由词根、三维部件名，**不够**。

| 仍在复用的流水线 | 东数西算知产公共服务系统 | 大数据结果可视化展示系统 |
|---|---|---|
| 工程拓扑 | `src/{api,components,router,stores,styles,three,views}` + `server/{api,domain,db,middleware}` | 完全同构 |
| 应用壳 | 顶指标带 + 底 15 踏板 | 顶灯轨 + 底踏板 |
| 首页 | 左简报 / 中厂房孪生 / 右栈 | 左批次树 / 中展厅孪生 / 右审片栈 |
| 三维公式 | 玻璃壳 + 分区地坪 + 柱网 + 路径光点 + 4～5 相机 + 5 态 | 同公式，只换展墙/沙盘 |
| 闭环套件 | 核验 → 异议/发布 → 复查拉帘 → 封存廊 | 审片 → 发布 → 回放轨 → 封存柜 |
| 留痕 | `PR-#1 准入与工程骨架` `PR-#2 主工作台与三维现场` | 同序换词 |

下一案若再出现其中任意 3 项，**第一关失败**，必须换族重做，不得靠改标题交差。

---

## 1. 先读近案指纹，再设计

编码前必须扫描工作区最近 2–3 个垂直系统（优先看 `设计说明.md` 的导航/壳/三维/登录构图），写出本项目的 **禁用清单**。至少禁用：

1. 最近一案的导航拓扑（顶轨底踏、左栏三组、底河、双轨等）
2. 最近一案的首页主轮廓（左树中孪生右栈，是当前最高频雷同）
3. 最近一案的三维现场族（玻璃厂房园 / 规划馆展厅 / 工地六分区）
4. 最近一案的登录构图（全屏装置+底横条 / 上吊箱下表单 / 左盘右表）
5. 最近一案的签名元素类型（闸门天平 / 切片灯箱 / 配比盘）
6. 最近两案都用过的后端目录名 `server/api + server/domain + server/db`

指纹写入 `设计说明.md`「近案禁用与本案换族」，并同步一份到工作区 `_soft_work/recent-system-fingerprints.md`（不进交付根）。

---

## 2. 必须换族：六张牌各抽一张，且不得与近两案相同

每个新项目从下表**各选且只选 1 个主族**。选择必须能用软件全称解释，禁止随机换色冒充换族。

### 2.1 信息架构族（决定页数，不再锁死 15）

| 族 | 页数 | 适用名称 | 禁止拿来凑页的东西 |
|---|---|---|---|
| A 短链深判 | 9–12（含登录） | 词根少、判断单一 | 对照页、台账页、留痕页拆成三张同构皮 |
| B 现场工序 | 12–14 | 施工、巡检、配比、进场 | 把工序再复制成“总览/台账/对照” |
| C 证据卷宗 | 11–14 | 审核、权属、检测、公示 | 再加一张无判断的“海报墙” |
| D 展陈编排 | 10–13 | 展示、发布、对照、上墙 | 再做一页和首页同轮廓的巡展 |
| E 空间分区 | 12–15 | 厂站、管网、仓储、枢纽 | 每个分区一页换标题 |
| F 多角色接力 | 11–15 | 跨角色审批/派发 | 每角色一页同一表格壳 |

**覆盖声明**：技能正文里若出现“十五个业务页 / 十五页布局”，一律理解为“由本表编译出的 9–15 个界面，含登录”。禁止为凑 15 而克隆页面。

### 2.2 应用壳族（连续两案不得同族）

| 族 | 骨架 | 近案占用 |
|---|---|---|
| 壳-踏板台 | 顶带 + 底一排节点 | **东数西算、大数据已占用，下一案禁用** |
| 壳-左架 | 左分组导航 + 顶丝带 | 建筑施工已占用 |
| 壳-工作票 | 无常驻导航，顶栏只留当前票号，翻页靠票面“下一工序” | 可用 |
| 壳-墙柜 | 左侧或底部是可抽的柜门/卷宗脊，无按钮踏板 | 可用 |
| 壳-仪表盘桌 | 主区是台面，模块是桌上器物，不走菜单 | 可用 |
| 壳-地图先 | 先全幅平面/剖面，功能从锚点钻入，无顶 15 灯 | 可用 |
| 壳-双页夹 | 左文书右现场，模块是夹页标签 | 可用 |
| 壳-时间河 | 顶或底是时间刻度，不放 15 个同等按钮 | 东数西算已淘汰过，慎用且不得再配踏板 |

禁止再用 `grid-template-rows: 顶栏 + 1fr + 底踏板` 当默认 AppShell。

### 2.3 首页轮廓族（连续两案不得同族）

禁用（近两案）：**左对象列 + 中三维厂房/展厅 + 右结果栈**。

可选：

- 全幅现场，四角只有短铭牌
- 上文书下剖面
- 中央是一张会改写的规则/量表，三维缩在一角
- 横向胶片主舞台，没有孪生
- 双页对读，无三维或只有小预览
- 单列工序走廊，三维只在其中一站出现

全站最多 **2** 页使用“左树 + 中大舞台 + 右栈”。第三页出现即失败。

### 2.4 三维现场族（连续两案不得同族）

禁止把所有名称都编译成“玻璃厂房壳 + 环氧地坪 + 柱网 + 护栏 + 路径光点”。

| 族 | 看起来像什么 | 近案占用 |
|---|---|---|
| 厂站园 | 玻璃壳、分区地坪、机柜/货架阵列 | 东数西算占用 |
| 室内展厅 | 幕墙、沙盘、灯箱、参观流线 | 大数据占用 |
| 露天工地 | 基坑、栈桥、临边，无玻璃厂房 | 建筑施工占用 |
| 台面仪器 | 工作台、夹具、试件、量具，不是厂房 | 可用 |
| 剖面井巷 | 竖井/廊道剖面，沿深度读数 | 可用 |
| 桌案卷宗 | 几乎无室外，主模型是闸、册、秤、灯 | 可用 |
| 管网平面 | 以管线/路网为主，建筑只当参照 | 可用 |
| 单机解剖 | 允许“不是整厂”；名称是器件/焊缝/油液时必须走此族或台面族 | 可用 |

名称里没有厂、仓、站、厅、车间时，**禁止**默认厂站园。  
主场景仍要可点选、有状态差、有相机预设，但不要求每案都堆到“整厂 48 几何”。器件/展陈/文书类以**可识别对象层级**为准，不要为凑部件数复制护栏料箱。

### 2.5 后端拓扑族（连续两案不得同目录名）

近两案都是 Express + `server/api` + `server/domain` + `server/db` + `middleware/auth.ts`。下一案必须换至少 3 项：

- 语言或框架：FastAPI / Express 换目录语义 / 同一 Express 但入口不叫 `server/index.ts`
- 目录：`backend/routers` `backend/rules` `backend/store` 或 `api/handlers` `api/engine` `api/persist`
- 权威对象名：不要再叫 `ledger` + `archives` + `publishService` 三件套
- 状态机形状：不要再写“整备→校准→待审→发布→封存”的换词版
- 测试文件名与断言对象必须带本项目词根

后端必须真实存在；换族不是改成前端假接口。

### 2.6 手册叙事族（连续两案不得同序）

禁止再按「软件定位 → 运行准备 → 术语表 → 15 页逐页 → 闭环 → 留痕」同序开写。内容仍要覆盖安装、登录、全部页面、闭环、异常、留痕，但：

- 章名必须含本项目对象词（开厅 / 开闸 / 开工 / 开柜），禁止连续两案都叫“软件定位”“术语与状态”“页面总览”
- 可把闭环放到第 2 章，安装放到后部；可把异常拆进各章，不再单开万能异常章
- 步骤句长必须明显不均；同一章里禁止连续 3 步都是“定位控件 → 点击 → 状态变为”
- 失败提示必须抄界面原文，禁止“操作失败，请重试”

## 3. 密度与动作：按页职责，不按统一配额

旧规则“每页 ≥16 入口、每页工业诊断台”会把所有页面逼成同一张脸。

改为：

- **主判断页**（全站 2–4 页）：≥14 个有效入口，≥5 个专属写库/改视图动作，允许高密度
- **工序/文书页**：8–14 个入口即可，强调字段、校验、回退
- **现场/模型页**：入口可以少，但状态切换必须肉眼可辨
- 全站至少 3 页高密度，而不是 5 页都做成左中右诊断台
- 禁止用重复的“刷新 / 导出 JSON / 同步孪生 / 计数 / 只看高优”凑 16

## 4. 文案去模板 / 去 AI 腔（系统界面 + 项目内手册）

除 `操作手册去AI味与研发留痕.md` 的禁用词外，本工作区已出现、下一案禁止再写的套话：

- 本系统只做一件事：……
- 换到××后，××无法原样复用
- 权威状态在服务端，Pinia 只缓存
- 顶票根带 / 底闭环踏板 / 无固定左栏
- 名称删除测试通过 / 行业替换测试通过（这些只写进设计说明，**禁止写进操作手册正文**）
- 闸口未开启 / 展厅闸口与当日展次台账不符 —— 句式可借鉴，但必须换成本案对象，不得再造“××闸口与××台账不符”
- PR-#1 准入与工程骨架、PR-#2 主工作台与三维现场（脚本已改；手工也不得沿用）

界面按钮禁止再默认叫：开启××闸口、退出闸口、重映台账、同步孪生、导出态势。按名称另起动词。

## 5. 源码指纹最低差

与最近一案对照，必须同时满足：

1. `AppShell` 的 DOM 骨架不同（不是改 class 名）
2. 路由数量或层级不同，或主路径段完全不同且无 `hub-desk`/`gallery`/`twin`/`archive` 这种通用三段连用
3. 至少 2 个领域文件职责是本案独有（例如只有本案才有的公式、冲突、扣分），不是 `publishService`/`archive` 换词
4. 三维工厂函数名、分组层级、主对象与近案不同；禁止复制 `box()/cyl()` 厂房脚手架后只改尺寸
5. 登录页 DOM 层级与近案不同
6. 手册前 4 个一级标题与近案不同
