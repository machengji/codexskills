# frontend-design 接入规范

本技能在**名称编译与三案选型之后、批量编码之前**，必须先应用 `frontend-design` 的设计原则，把“垂直业务正确”升级为“垂直且好看、有记忆点、不像 AI 默认模板”。

## 1. 强制读取

编码前必须完整读取：

- `E:\machengji\.dsh\skills\frontend-design\SKILL.md`

若该路径不存在，则读取 Anthropic/OpenAI 同源 `frontend-design` 技能；仍找不到时，至少按本文件第二节的硬清单执行，并在 `验收记录.md` 写明“外部 frontend-design 缺失，已按本接入规范执行”。

## 2. 接入时机（不可跳过）

```text
名称语义拆解
→ 三案竞争与选型
→ 【frontend-design 视觉精修】  ← 本文件
→ 登录页/全页自主创新与异构矩阵
→ 跨项目防重复
→ 设计说明与前置验收通过
→ 才允许批量写页面
```

禁止顺序：

- 先写通用壳再“后期美化”
- 只做业务异构，不做字体/色板/签名元素精修
- 把 frontend-design 降级成“参考建议”而不写入 `设计说明.md`

## 3. 必须产出的视觉方案（写入设计说明.md）

在选定业务视觉方向后，用 `frontend-design` 做第二轮精修，至少写出：

1. **Subject grounding**  
   一句话点名：核心对象、主要使用者、本页/本系统唯一任务。

2. **Color tokens（4–6 个命名色）**  
   每色给中文名 + hex + 业务用途；状态色必须有业务含义。  
   禁止无依据的彩虹色和万能霓虹。

3. **Type roles（至少 2 种角色）**  
   显示/标题字体、正文字体；必要时加数据/标签用等宽或工具字体。  
   写清字重、字号阶梯、字距/行高意图；字体选择必须服务名称对象，不得永远用同一套 Inter/系统默认脸。

4. **Layout concept**  
   一句话布局概念 + ASCII 线框（至少覆盖登录页与首页）。  
   说明主视觉重心、阅读方向、工具区、结果区。

5. **Signature element（唯一记忆点）**  
   只保留一个可被记住的签名元素；其余区域克制。  
   必须能回答：来自名称哪个词、帮助什么判断、为何比通用后台更好看。

6. **Motion plan**  
   写清“用/不用”动画；若用，只服务主体对象或关键状态切换，禁止散点式 AI 动效。

7. **Copy as design**  
   关键按钮、空状态、失败提示的中文口径：动作+对象、主动语态、不卖弄、不空泛。

8. **Anti-default critique（反 AI 默认审美）**  
   明确写出本方案如何避开以下默认脸，除非名称本身要求：
   - 暖奶油底 + 衬线大标题 + 陶土色点缀
   - 近黑底 + 单一酸绿/朱红点缀
   - 报纸细线密栏零圆角
   - 万能紫渐变 / 玻璃拟态 / 无意义发光边
   - 默认 shadcn 卡片墙 + Inter 无性格排版

## 4. 与本技能原有门禁的叠加规则

| 原门禁 | 叠加后额外要求 |
|---|---|
| 三案竞争 | 胜出案必须再过 frontend-design 精修，不能只写隐喻口号 |
| UI 创新指纹 | 色板/字体/几何/签名元素必须来自 frontend-design 方案，不得事后补空 |
| 好看可检 | 除层级与对比外，还要能指出字体配对、签名元素和反默认审美证据 |
| 登录页创新 | 登录页首屏必须承载签名元素或名称对象，不得只换文案 |
| 页面异构 | 异构改变结构，frontend-design 保证全站视觉语言统一且精致 |
| 跨项目防重复 | 十维差异中至少包含“字体角色 / 签名元素 / 主色材质”三项之一与近期案例不同 |

## 5. 实现约束

- 写 CSS/Tailwind 时，颜色与字号必须从 `设计说明.md` 的 token 派生，禁止临场再发明一套。
- 大胆设计只集中在签名元素；信息区保持清晰可读。
- 选择器 specificity 避免互相抵消；间距系统保持一致。
- 响应式、可见焦点、减少动效（`prefers-reduced-motion`）作为质量地板，不单独吹嘘。
- 中文界面文案遵循 frontend-design 的 writing 原则：从用户侧命名、动作一致、失败可修复、空状态可行动。
