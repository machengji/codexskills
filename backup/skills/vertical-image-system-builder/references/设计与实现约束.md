# 设计与实现约束

## 一、不可妥协的共同标准

- 围绕系统全称选一个现实生活中可执行的单点业务，形成“现场影像进入、判断处理、人工操作、结果变化、复查沉淀”的闭环。
- 默认做高完成度前端模拟，不为了满足技术栈强行编写低质量后端。模拟必须有真实状态变化、可回退步骤、可追溯记录和可视结果。
- **三维是默认交付物**，须达到 [三维建模完成度](三维建模完成度.md) 的**工业现场级**数字孪生门槛（整厂/产线/仓储观感），不得省略、用静态图代替，或用虚空单机冒充。
- 所有可见文字、错误提示、按钮、图表标题、空状态和注释使用自然专业中文。禁止英文、英文缩写、版本号、机构名、品牌名、人物名和计量单位名称。图表标题不能脱离软件名称对应的业务对象和判断。
- 文件使用 UTF-8 无签名编码；中文直接存储，禁止 Unicode 转义。
- 整页固定视口并禁止全局滚动。局部面板、列表、图像轨道和详情区可独立滚动。
- 登录和注册**功能**保持简单，只提供账号、密码和切换入口，不堆叠复杂身份功能；但**视觉与布局必须创新**，并与软件全称强绑定。
- 登录页禁止直接套用“左图右表单 / 居中白卡片 / 全屏模糊背景 + 通用表单”而不改结构；必须有名称对象或现场工具构成的首屏主体、业务准入语境和进入后落点说明。
- UI 必须符合标题：术语、对象、材质、操作和结果都应服务软件全称；把标题换成无关名称后界面应明显违和。
- 界面必须创新且好看：先走 frontend-design 精修，主次清晰、色彩克制、字体成对、材质统一、对比足够、首屏有签名元素；禁止脏乱堆叠、万能霓虹、无意义玻璃拟态、AI 默认脸和模板脸后台。

## 一-A、页面功能复杂度（工业诊断台级，强制）

生成的每个业务页必须达到工业诊断/解析/预警工作台复杂度，而不是后台展示页：

- 首屏 ≥3 个并发工作区：对象/工况器、中央解析舞台、规则/结果/风险区；
- 有效操作入口 ≥16，页面专属动作 ≥5，且有业务语义反馈；
- 全站 ≥5 页达到高密度诊断台加强标准（连续指标条 / 多层对象树 / ≥5 工况对照之一）；
- 禁止卡片墙凑按钮、单表低互动、空“操作成功”。

细则与验收字段见 [页面异构与密度门禁](页面异构与密度门禁.md)。

## 一-B、独立开发与反换词（软著鉴别材料预备）

本项目源码和项目内文档会成为软著鉴别材料来源。必须从实现阶段避免“模板化 / 与已登记材料雷同、批量替换关键词”：

- 禁止复制旧项目或同级案例后，仅替换软件名、行业词、颜色、图标、文案。
- 路由树、Store 形状、领域类型、状态枚举、专属页面文件、核心业务函数必须本项目新写，并在 `设计说明.md` 记录**源码原创指纹**。
- 共享只能下沉到无业务语义的原子组件；不得用单一页面生成器/统一 CRUD 壳承载全部业务页。
- 核心判断链路、状态机、三维/影像联动、规则结果区必须有真实可运行代码，保证后续源程序鉴别材料具有代表性。
- 与同级最近 1–3 个案例做代码层对照；高度同构即失败，需重构后再验收。
- `设计说明.md` / `操作手册.md` 也必须项目专属重写，禁止旧案换词。

## 二、把软件全称编译为界面，而不是替换标题

不要把系统名称替换到既有模板中。按以下顺序独立设计：

1. 将名称拆成六类语义：核心对象、关键动作、真实场所、判断结果、主要使用者、现场工具。
2. 建立“名称语义 → 界面后果”映射：对象决定舞台形状与组件几何；动作决定阅读方向、导航和动效；场所决定材质、光线与空间密度；结果决定状态色与图表表达；使用者决定信息层级；工具决定控制器与按钮形式。
3. 选取最真实的亚洲生活或行业现场，写出使用者必须完成的一个关键判断。
4. 先提出三套候选视觉方向：对象/结构隐喻、流程/时间隐喻、场所/工具隐喻。分别按名称贴合度、判断效率、三维可表现性、跨项目新颖度四项打分，选择最高者；在 `设计说明.md` 写明另外两案的淘汰理由。
5. **强制应用 frontend-design 视觉精修**：读取 `E:\machengji\.dsh\skills\frontend-design\SKILL.md`，按 [frontend-design接入](frontend-design接入.md) 对胜出案产出色板 4–6、字体角色、布局概念/ASCII、签名元素、动效计划、文案口径与反 AI 默认审美自检；未完成不得进入指纹定稿。
6. 让影像成为判断依据，让三维模型成为空间、结构、变化或处置的辅助依据。
7. 从对象的材质、工具、结构、光线、路径、档案或工序中提取视觉令牌与**可建模部件清单**；颜色与字体必须与 frontend-design 方案一致，禁止临场另起一套。
8. 将工作流拆为不少于十五个职责明确的界面，不允许照搬固定菜单集合。
9. 为每个界面指定不同主体轮廓、布局母版、图像角色、图表角色、模型角色和按钮分布，并写出系统级UI创新指纹与页面重复预算；登录页/首页首屏落地签名元素。
10. 为每个页面写“名称词根—业务对象—操作—结果”映射；页面内容不能只靠替换标题、数字和颜色成立。
11. 图表按需设计而非默认铺设：每个 chart 必须登记数据来源、服务的业务判断、点击后的状态后果；无法登记的图表不进入实现。

必须同时通过三个替换测试：

- **名称删除测试**：删除系统名称后，仍能看出具体行业对象与现场判断；否则术语与视觉不够垂直。
- **行业替换测试**：换成另一行业后，菜单、模型部件、动作和数据结构不能原样复用；否则业务切口过泛。
- **项目互换测试**：把本项目的导航、首页或页面骨架放入最近案例后应明显不协调；若仍自然适配，说明界面外壳不够专属。


## 二-A、登录页创新与多布局好看标准

### 登录页
1. 先写登录页独立性记录：名称映射、构图、记忆点、与通用模板差异、失败反馈业务语言、进入首页后的状态变化。
2. 登录页首屏必须出现软件全称对应的对象/场所/工具隐喻，可用程序化三维、Canvas 结构或材料化面板，不得用无关网图凑氛围。
3. 登录页布局骨架必须与首页不同；登录成功后进入的应是业务现场，而不是同一卡片换位置。
4. 登录页抽检与业务页同级；模板化登录直接判定视觉创新失败。

### 好看标准（可验收，含 frontend-design）
1. 一眼能找到主任务区，次要信息退到侧翼或底层。
2. 全站 4–6 个**命名**色彩令牌（来自 frontend-design 方案），状态色有业务含义，不靠彩虹色制造热闹。
3. 至少两套字体角色（显示/正文，必要时工具/数据字体）成对且可解释，不是永远同一套默认脸。
4. 几何、描边、阴影、圆角/切角来自名称对象，不混用多种无关风格。
5. 至少一处名称专属记忆点/签名元素出现在登录页或首页首屏；大胆设计只集中这一处。
6. 信息密而不堵：分组、对齐、节奏明确；禁止同形卡片墙和无对比按钮阵列。
7. 反 AI 默认审美自检通过：无无依据的暖奶油衬线陶土、近黑酸绿、报纸细线密栏、紫渐变玻璃卡。
8. 实现用色/用字必须派生自 `设计说明.md` 的 frontend-design 方案，禁止临场第二套风格。

### 多布局
1. 从布局母版库中选择、拆解或重组，十五页不得只打乱同一骨架。
2. 同一母版最多两页；相邻页至少改变视觉重心、阅读方向、组件骨架、信息层级、模型/影像角色、工具位置、按钮密铺、结果位置中的五项。
3. 导航拓扑、主舞台位置、面板数量与面积关系、按钮密铺方式不得在三页以上同时重复。
4. 缩略拼图隐藏标题并缩小到 20% 后，页面职责仍可凭轮廓识别。

## 三、名称驱动的视觉方向与跨项目原创

禁止预设所有项目都采用同一种浅色中性工作台、暗色驾驶舱或左栏卡片后台。先从系统全称提取对象、动作、场所和结果，再生成本项目的视觉基因：

- **视觉母题**：选择一个来自真实业务对象的结构隐喻，例如账本折页、站场管廊、切片轨道、证据封签、物料刻度或信号脉络；不得直接套用上一个项目的母题。
- **色彩与材质**：从对象的真实材料、环境光线、行业标识和状态风险中提炼3–5个主令牌；不得每次固定使用雾灰青绿、深蓝霓虹或暖米色。
- **字体与信息层级**：为展示标题、正文、数据和工具标签定义不同角色；字号、字重、字距和数字形式应服务该行业的阅读方式，而不是沿用统一后台字号表。
- **几何语言**：从对象的边缘、容器、票据、机械结构或空间路径推导圆角、切角、分隔线、面板厚度和阴影；禁止全站统一玻璃卡片。
- **导航拓扑**：依据工作流选择顶部舱轨、账本页签、流程脊柱、档案索引、空间罗盘、分层工具架等结构；禁止无理由固定为240像素左侧栏加顶部标题栏。
- **标志性交互**：至少实现一个由名称直接推导、其他案例没有的视觉交互，并在设计说明中写出“名称语义→视觉结构→业务后果”的映射。


### 页面级组合规则

- 共享只下沉到按钮、标签、图表、画布工具、模型控制器等原子或小型组合组件；不得用一个通用页面组件和固定面板清单渲染全部业务路由。
- 页面配置数据可以驱动文案和数据，但不能决定全部结构。强相关页面可共享一个职责模板，最多覆盖两个页面，并必须在视觉重心、阅读方向、工具位置、结果位置和模型/影像角色中改变至少五项。
- 同一导航内容排列、主舞台位置、面板数量与面积关系、按钮密铺方式不得在三页以上同时重复；三维舞台固定在同一区域的页面不得超过总页数三分之一。
- 公共品牌区可以稳定，但不得占据大部分首屏或让十五页只剩同一内容网格。页面职责必须在缩略图中通过轮廓而非标题被识别。
- 不得用随机颜色、随机圆角或随机卡片坐标制造“差异”；所有变化必须来自名称语义、业务步骤或判断方式。

大胆设计集中于一个独有记忆点，其余区域保持清晰可读。相邻页面至少改变视觉重心、阅读方向、组件排列、信息层级、图像/模型角色、工具位置、按钮密铺和结果位置八项中的五项。

### 跨项目防重复审计

工作区存在已完成案例时，编码前抽查最近或最相似的3–5个项目，至少比较：导航拓扑、首页轮廓、色彩材质、字体层级、组件几何、模型舞台形状、图表表达、按钮分布、背景纹理和标志性交互。本项目必须至少七项明显不同；最近两个项目若已连续使用同类导航、首页舞台或配色，本项目在对应维度必须改换方向。不得复制整段页面CSS、页面配置数组、通用六面板网格、单一页面生成器或上一个项目的首页布局后替换文案。

### 全页轮廓验收

实现后截取全部业务页面同尺寸全页图并制作站内缩略拼图；另把本项目首页与3–5个同级案例首页并排制作跨项目对照。缩小到20%后，用户仍应在隐藏标题时通过主体轮廓区分页面职责和项目身份；出现三页以上同骨架、首页只能靠名称辨认、或首页与同级案例高度相似，判定视觉创新失败并重做。

可从以下布局母版中选择、拆解或重组，十五页不得重复；不得按该列表固定顺序生成，也不得在不同项目中复用同一组母版组合：

- 中央现场三维舞台与左右数据舱（数字孪生主屏，优先用于核心页）；
- 中央现场舞台与四角浮层；

- 三栏影像处理台与底部步骤轨道；

- 环形工具盘与画布标注室；
- 多列流转看板与嵌入式影像卡；
- 横向影像胶卷与纵向细节窗；
- 非规则信息拼贴与小型图表矩阵；
- 证据链关系画布与时间卡；
- 结构树、三维近景和材质/状态控制器；
- 流程编排画布与方案参数板；
- 分区地图与证据堆叠区；
- 交错卡片流与多级悬浮工具条；

## 四、影像设计规则

完整细则见 [真实网图案例规范](真实网图案例规范.md)。

- 严禁调用任何生图能力或图像生成功能，包括 imagegen；生图不得冒充真实案例。
- **中国境内真实网图案例默认启用**：每个项目必须下载并本地化 ≥6 张与软件全称强相关、地点明确属于中国境内（默认中国大陆）的真实网上图片，作为案例/证据/对照底图；至少覆盖 3 个业务页；核心影像链路至少 2 张中国真实原始案例图可载入并处理。除非用户明确指定外国国家/地区，否则外国场景图片数量必须为 0。
- 来源优先级：用户提供的中国图片 → 项目内已有且地点可证的中国图片 → 许可清晰的中国公开真实网图（Wikimedia / 国内政府院校行业公开资料 / 图库等）→ 其他可追溯且地点明确为中国的真实图。图片托管网站可位于境外，但画面实际地点必须是中国境内。
- 每张真实网图必须登记：本地路径、原始 URL、来源站点、许可/授权、`country: 中国`、省市/具体地点、地点依据、名称词根、使用页面、业务角色；代码只引用本地文件，外链不得作为唯一主依赖。中国图片不足时继续搜索，不得用外国图片补位。
- 登录页若用真实图，必须服务名称对象/场所，不得用无关风景凑氛围；登录页构图与签名元素要求不变。
- 禁止外国场景图片、无关装饰网图、无台账热链、同图复制凑数。中国真实图下载失败时记录失败并换中国图片重试；整项目中国真实网图低于门槛则素材门禁不通过。
- 中国真实图不足的辅助槽位，才使用 Canvas、矢量结构、纹理切片或程序化三维材质，并标注“前端演示素材”；不得使用外国图片补位。
- 影像不能只是背景，必须承载至少一种处理或判断：画面校正、亮度调整、细节增强、局部定位、遮罩、轮廓、前后对比、标注或变化展示。
- 前端模拟可以使用 Canvas 的像素处理、遮罩绘制、叠加层、局部裁切和确定性生成结果。必须让处理前后可见、可切换、可回退、可记录。
- 每个核心页面至少放置两幅以上小尺寸精致图像或局部结果，不让单张大图占满整个页面。
- 图表不是基础标配，只做名称对应业务判断的辅助；宜使用小型趋势、状态分布、处理轨迹、关联关系或变化对比，并支持点击联动到案例、区域、任务或模型。无判断用途的图表、装饰性环图、假指标、图表墙和为了凑密度的 chart 必须删除，改用证据列表、状态矩阵、时间轨道、影像标注或对象明细。

## 五、三维设计规则（摘要；细节以完成度文档为准）

完整门槛见 [三维建模完成度](三维建模完成度.md) 与 [Three.js高级建模技能接入](Three.js高级建模技能接入.md)。此处为设计层硬约束：

- 三维对象必须由系统名称决定：实体对象、空间现场、局部结构、层级剖面、处置区域或时间状态，不得无关装饰。
- **先路由 Three.js 技能再建模**：读取 `threejs-choose-skills` 与基线/扩展 `threejs-*`，在 `设计说明.md` 写技能路由表；未路由不得写主模型工厂。
- **程序化分层装配（现场级）**：整场/产线 = 场地环境 → 分区 → 设备族 → 细节 的多命名部件 Group，对齐 object-sculptor + procedural-geometry + procedural-materials；主场景最低分区≥2、设备族≥3、部件≥24、几何≥48、PBR材质≥6、装配层级≥4、路径层≥1、业务锚点≥8。须有地坪/通道/柱网或厂房壳、护栏等现场构件与工业色语义；表现主光阴影/接触暗部、路径流动、HUD 同源叠层。**禁止**只摆放单个立方体、球体、圆柱体、无语义积木堆或虚空单机充当整场。
- **观感对标**：主孪生页须能对照仓储整场总览、半透明建筑壳+流程轨迹、实体车间沉浸三类参考之一；默认相机为高位总览，并提供 ≥4 视角与 ≥4 业务状态。
- **路径与 HUD**：至少 1 条工艺/物流路径层可显隐或动画；主孪生页 ≥3 个与选中设备/分区同源的浮层信息。
- 主工作台须让三维对象占主要视觉权重，但舞台位置、形状和业务舱拓扑必须由系统名称决定；只有业务上合理时才使用“中心三维+左右舱”。模型须有地坪、台座或其他尺度参照，避免悬空无尺度。
- 至少在五个页面出现模型或模型预览，但每次承担不同职责：总览定位、单机比对、剖切诊断、状态模拟、影像映射、方案预览、经验回放或成果展示；主页复杂度最高。
- 每个三维控制必须产生视觉变化：视角预设、局部隐藏、剖切深度、纹理/材质切换、问题区域高亮、影像映射开关、前后状态切换、时间播放或处理效果模拟。
- 强制：**≥4 业务状态**、**≥3 相机预设**、**部件点击与侧栏联动**、**阴影接地**；状态与选中部件进 Pinia，可留痕、可回放。
- 名称扩展环境（建筑群/水体/大气/粒子/运动等）必须能从全称词根解释，且有可见后果；禁止无依据堆特效。
- 半透明结构透视与实体写实可按页切换，但都须保持业务可读，不是纯特效。

## 六、前端模拟工作流

为每一个案例维护统一状态：原始影像、影像版本、处理步骤、重点区域、人工标注、三维状态、处置动作、复查结果、操作记录和归档状态。

推荐使用如下行为链路，并改写为系统专属业务词：

```text
载入现场影像
→ 检查画面
→ 执行前端图像处理
→ 发现或标注重点区域
→ 在模型中定位或模拟
→ 制定并执行处置动作
→ 载入复查结果
→ 比对变化
→ 保存过程记录与成果
```

按钮不能只有提示框。每次交互应至少触发一个真实结果：

- 切换图像版本、叠加层或局部对比；
- 更新重点区域、颜色、备注或确认状态；
- 更新模型姿态、层级、材质、高亮区域或相机预设；
- 更新任务卡、流程节点、进度和时间记录；
- 打开具有明确操作内容的抽屉、弹窗或面板；
- 生成并展示可下载的前端成果数据；
- 记录操作并允许查看前后状态。

## 七、页面密度与按钮规则

- 每个业务页面至少十二个有用途的操作入口；不要为了凑数量重复“确认、更多、编辑”。至少 3 个操作必须是该页面独有，并实际改变状态、视图、模型、影像、任务、筛选、流程或留痕。
- 按钮文案使用动作加对象，例如“校正当前画面”“锁定观察区域”“映射至立体位置”“建立复查节点”“切换告警高亮”。
- 不同页面的按钮分布必须不同：顶栏工具带、侧边工具架、环形工具盘、底部控制轨、影像悬浮条、卡片内操作、右键菜单、模型控制台、浮动快捷盘等。
- 所有操作都要给出中文反馈，禁用状态要说明无法操作的原因。
- 信息密集但不混乱：以分组、优先级、局部滚动、折叠区、标签和快捷操作维持清晰。

## 八、操作手册交付

- 默认在项目根目录生成 `操作手册.md`，详细规范见 [操作手册规范](操作手册规范.md)。
- 手册必须与真实页面和交互一致，不能用未实现功能充数；关键页面优先附实际运行截图或截图文件路径；手册配图禁止无关网图，案例来源说明指向设计说明台账。

## 九、实现验收清单

在交付前逐项确认：

- 不少于十五个有不同业务责任且主体轮廓可区分的界面；
- 已完成 frontend-design 视觉精修方案（色板/字体/布局/签名元素/反默认审美）并写入设计说明；

- 已与同级3–5个案例完成十维防重复比较，至少七项明显不同；
- 已生成十五页全页缩略拼图和跨项目首页对照，隐藏标题并缩小到20%后无三页以上同骨架且项目身份可辨；
- 三套候选视觉方向、评分、淘汰理由、frontend-design 精修与名称语义映射完整；逐页异构矩阵和页面重复预算完整；
- 每页有效操作入口不少于 16 个、专属操作不少于 5 个，并满足工业诊断台级并发工作区与业务语义反馈；
