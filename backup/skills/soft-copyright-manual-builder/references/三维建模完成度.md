本文件是 `vertical-image-system-builder` 的三维专项验收标准。

> 自接入 `threejs-complete-set-of-skill` 起，三维默认按**高级程序化真实建模**执行。  
> 必读配套规范：[Three.js高级建模技能接入](Three.js高级建模技能接入.md)。  
> 编码前必须路由并阅读相关 `E:\machengji\.dsh\skills\threejs-*/SKILL.md`。
>
> **观感对标（强制）**：主三维必须达到“工业数字孪生工厂/仓储/产线”级完成度，而不是单机玩具模型。  
> 对标方向（风格可随名称词根切换，但完成度不得低于此）：
>
> 1. **仓储物流整场总览**：高架货架阵列、中央主通道、多层输送线/辊道、包装机台、天车/立柱、灰地坪分区、蓝结构+绿机台+黄安全色体系。  
> 2. **半透明建筑壳 + 流程轨迹**：厂房玻璃/实体外壳、内部绿机台集群、红色/青色工艺路径或管廊流线、告警锚点、人物比例尺、深色 HUD 数据舱。  
> 3. **实体车间沉浸孪生**：绿色环氧地坪、钢柱与屋顶桁架、安全围栏、工业机器人/工位、物料垛、车间灯带、顶部业务导航与四角 KPI 叠层。

## 一、对标什么

交付中的三维不是装饰插画，而是**可操作的业务现场**：

- 第一眼能看出是**整厂 / 产线 / 站场 / 仓储 / 车间工段**，而不是漂在虚空里的一台孤立机器；
- 有可识别的**分区、通道、地坪、建筑/结构骨架、设备族、物流或工艺路径**；
- 能换视角看清结构关系与现场尺度；
- 能切换运行 / 告警 / 停机 / 检修等状态，且状态落在具体工位或设备上；
- 能点选部件并与侧栏、告警、趋势、影像、HUD 标注联动；
- 截“主视图 / 状态变化图”时，分区、路径、护栏、标注牌、材质分区有明显差异。

## 二、技术默认（Three.js 技能增强）

- 库：Three.js + 轨道控制（或 camera rigs 等价封装）；Vue 中独立 `Scene` 组件，销毁时释放几何/材质/渲染器/控件。
- 建模方式：**现场级程序化分层装配**为主，遵循：
  - `threejs-object-sculptor`：对象拆解与重建计划（先现场总图，再设备）
  - `threejs-procedural-geometry`：网格/扫掠/实例化/轮廓（货架、围栏、输送线优先实例化）
  - `threejs-procedural-materials`：PBR 材质图谱与工业色分区
  - `threejs-procedural-buildings-and-cities` 或等价建筑/厂房骨架技能（名称含工厂/车间/站场/仓储时强制）
  - `threejs-procedural-motion-systems` 或粒子/路径技能（输送、流转、巡检、告警脉冲）
- 光影默认遵循：
  - `threejs-scalable-real-time-shadows`
  - `threejs-ambient-contact-shading`
- 相机默认遵循：`threejs-camera-controls-and-rigs`
- 验收默认遵循：`threejs-visual-validation`
- 允许：程序化金属/漆面/玻璃/橡胶、环氧地坪、护栏、发光状态条、Edges/LineSegments、接触阴影、克制 AO、半透明厂房壳、工艺流线。
- 禁止：仅 `BoxGeometry`/`SphereGeometry` 一个 mesh 代表整机；纯 CSS 伪 3D；静态 PNG 假模型；空黑底板 + 单机悬浮；无名称依据的霓虹 bloom / 宇宙特效堆砌。
- 不依赖外部付费模型、不调用生图贴图充当整机。

## 三、主场景结构最低规格（现场级抬升）

对**主孪生场景**至少满足：

| 项 | 最低要求 |
| --- | --- |
| 场景类型 | **现场级数字孪生**（整厂/产线/站场/仓储/车间工段之一），禁止“单机悬空”作为主场景 |
| 功能分区 / 产线区 | ≥ **2** 个可命名分区（如入库区/加工区/成品区，或 A 线/B 线） |
| 设备/构筑物族 | ≥ **3** 套职责不同的对象族（如货架、输送线、机台；或机器人、围栏工位、料架） |
| 命名部件（可点选 Group/Mesh） | ≥ **24** |
| 几何体实例（可复用/实例化） | ≥ **48** |
| 材质种类（PBR 参数可区分） | ≥ **6** |
| 装配层级 | ≥ **4**（场地环境 → 分区/产线 → 设备主机 → 连接件·护栏·线槽·指示） |
| 业务锚点（可高亮故障/工位/测点） | ≥ **8** |
| 工艺/物流路径层 | ≥ **1** 条可见路径（输送带、辊道、管廊、巡检轨迹、AGV 路线或工艺流线；可动画） |
| 建筑/结构环境 | 至少具备：地坪分区 + 承重/柱网或屋顶桁架或墙体/玻璃厂房壳 中的 **2 类** |
| 安全与现场构件 | 护栏/围栏/立柱/平台/线槽/灯带/料箱 中至少 **3 类** |
| 工业色语义 | 结构色、设备色、安全色、告警色可区分；禁止全场同色塑料灰 |
| 比例尺 | 人物剪影、标准通道宽、托盘/料箱或等价尺度物至少 **1 类** |
| 灯光 | 环境光 + 主方向光（投阴影）+ 补光/轮廓光；车间感优先暖白主光 + 冷色补光 |
| 阴影/接触暗部 | 至少一种真实阴影或高质量接触阴影/AO |
| 边缘与体积感 | 轮廓线/材质对比/AO 中至少两种 |
| HUD / 业务叠层 | 主孪生页至少 **3** 个与模型同源的浮层信息（设备铭牌、KPI 卡、告警气泡、路径图例等） |

对**单机特写页**：复用主现场中的子集，近景须额外增加 ≥2 类细节层（面板缝、螺栓阵列简化、护栏、线槽、显示条、格栅、铭牌等），并保留回到总览的入口。

对**主页**：必须是**现场总览级**复杂度，高于其他三维页（分区数、设备族、路径、环境构件、可点选锚点、状态演示密度、HUD 叠层）。

### 工业色与材质令牌（建议默认，可按名称改写）

- 结构钢 / 货架立柱：工业蓝或冷灰蓝  
- 设备壳体 / 机台：草绿、青绿或设备专用漆  
- 安全构件：黄 / 橙护栏、围栏、天车端头  
- 地坪：环氧绿、深灰通道、警戒斑马线  
- 流转路径：红/青发光管线或输送带深色皮带 + 侧板  
- 告警：红脉冲 emissive / 标牌  
- 玻璃厂房壳：低透明度 + 金属框 + 内部实色设备可读  

### 真实感九问（全是才算过）

1. 缩到 20% 是否仍能认出是该业务的**现场**，而不是散落积木？  
2. 是否同时看到**分区 + 通道 + 设备集群**，而不是单机居中？  
3. 是否有地坪、柱网/屋顶/墙壳、护栏中的现场骨架？  
4. 是否至少 3 类设备/构筑物族外形可区分？  
5. 是否至少 6 类材质在受光下可分辨？  
6. 是否有输送/管廊/巡检等**路径层**，状态切换时路径或工位有变化？  
7. 是否有接地阴影/接触暗部，而不是塑料悬空？  
8. 是否有人物/通道/料箱等尺度参照？  
9. 状态切换后 1 秒内，是否有不可否认的可见差异（色、光、显隐、运动、标牌）？

## 四、Three.js 技能路由（强制前置）

1. 读取 `threejs-choose-skills`。  
2. 启用基线技能包（geometry / materials / object-sculptor / camera / shadows / ambient-contact / image-pipeline / visual-validation / debugging）。  
3. 名称含工厂、车间、产线、仓储、站场、管廊、园区时，**优先**启用 buildings/cities、motion-systems、particles 等扩展。  
4. 按名称词根再启用 2–6 个扩展技能，详见 [Three.js高级建模技能接入](Three.js高级建模技能接入.md)。  
5. 写入 `设计说明.md` 的 **Three.js 技能路由表**；缺表不得编码三维。  
6. 路由表必须写清：现场总图拓扑、分区、设备族、路径层、HUD 叠层来源。

## 五、状态机（强制）

Pinia（或等价）中维护 `modelStatus` / `selectedPart` / `cameraPreset` / `sectionEnabled` / `activeZone` / `flowVisible` 等。

至少实现 **4** 种互斥或可叠加的业务状态，例如（按系统改名）：

1. 正常运行（路径流动、工位绿灯）  
2. 预警/告警（故障工位变色、脉冲 emissive、告警气泡、路径变红）  
3. 停机或锁定（局部设备停动、护栏/锁点提示）  
4. 检修/剖切/影像映射（外壳透视、舱内设备、只显示相关分区）  

每种状态切换后 **1 秒内** 画布可见变化，并写操作留痕。  
控件文案用业务中文，如“切换告警高亮”“显示物流路径”“剖切查看舱内”“飞到二号工位”。

## 六、相机与多视图（强制）

至少 **4** 个相机预设，可一键切换（带动画插值更佳）：

1. **高位总览**（默认首屏，对标工厂/仓储鸟瞰）  
2. 俯视或等轴总图（看分区与路径）  
3. 侧视或产线透视（看输送/工位关系）  
4. 关键设备 / 工位近景  

推荐再加：环绕自动演示（可关）、聚焦选中部件、分区飞入。  
实现口径对齐 `threejs-camera-controls-and-rigs`：相机主权清晰、大坐标不抖动、飞入可复位。

## 七、业务联动（强制）

至少打通：

- 点击部件 → 侧栏详情、告警列表、趋势过滤、HUD 铭牌  
- 侧栏/列表选中 → 模型高亮或相机飞入  
- 分区切换、路径显隐、状态切换、剖切平面、爆炸/展开（可选）  
- 与影像：映射平面、标注锚点、前后对比时模型同步版本  
- 与图表：点选序列高亮对应工位/设备/分区  

**无联动的纯展示旋转模型不算达标。**  
**只有单机、没有分区/路径/现场骨架的主场景不算达标。**

## 八、页面覆盖

- ≥ **5** 个路由页出现三维舞台或同步预览。  
- 职责必须分化，禁止五页复制同一相机同一状态：  
  - 整厂/产线总览孪生驾驶舱（主页，最复杂）  
  - 单对象/单工位诊断近景  
  - 结构剖切/透视/建筑壳分析  
  - 物流路径/工艺流转/方案预演  
  - 历史回放或成果对照  
- 非三维页可用缩略预览卡，但点击须能进入真三维页。  
- 名称扩展环境（水/建筑群/粒子等）应出现在最相关的 1–2 页，而不是十五页复制同一特效。

## 九、性能与工程

- 首屏模型应在合理时间出现；避免每帧重建全部 Geometry。  
- 货架、护栏、托盘、重复机位等优先 `InstancedMesh` 或共享几何。  
- 大现场用分层加载：先地坪/柱网/主路径，再设备族，再细节。  
- 组件卸载取消 animation loop、dispose 资源。  
- 构建期不得因缺 `three` 失败。  
- 画布容器须有明确高度，禁止高度为 0 导致“有代码无画面”。  
- 出现黑屏/白画布：先走 `threejs-debugging`，再谈业务功能。

## 十一、实现提示（给执行代理，非用户文档）

1. **先画现场总图，再做设备**：分区轴线、主通道、地坪、柱网/屋顶，然后才是机台。  
2. 用 `threejs-object-sculptor` 口径写拆解：Zone → Line → Equipment → Detail。  
3. 几何工厂按 `site / zone / rackOrLine / machine / robot / conveyor / fence / column / roof / flowPath / hudAnchor...` 分层命名。  
4. `materials.ts` 集中工业色令牌；禁止页面内魔法色散落。  
5. 货架、护栏立柱、托盘、重复工位必须实例化。  
6. 路径层单独 Group，支持显隐与告警变色；可沿路径做缓慢流动动画。  
7. 玻璃厂房壳：外壳低 opacity + 金属框 + 内部实色设备 + Edges。  
8. `applyModelState(group, state)` 统一改色/显隐/emissive/运动/路径。  
9. `cameraPresets` 默认给高位总览；`focusPart(name)` / `flyToZone(id)` 必备。  
10. HUD 铭牌用 CSS2D/Sprite/屏幕浮层均可，但必须与 `selectedPart` 同源。  
11. 先 shadows + 接地 + 地坪分区，再考虑 bloom/大气/粒子。  
12. 最后接 Pinia 与侧栏，避免先堆页面后补空画布。  
13. 每轮验收至少留：主总览图、告警状态图、近景图，并写入 `验收记录.md`。
