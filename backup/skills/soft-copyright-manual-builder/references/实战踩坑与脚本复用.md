# 实战踩坑与脚本复用（2026-09-11 水利四案固化）

> 本文是**操作手册**，不是规范条文。规范在 SKILL.md 与其余 references 里；本文只讲**实际跑起来会踩什么坑、怎么绕、哪些脚本能直接抄**。
> 每案开工前读一遍，可省掉大量返工。

## 一、Windows + PowerShell 环境硬坑

### 1.1 启动 dev server：不要用 `Start-Process npm`

`Start-Process -FilePath "npm" -ArgumentList "run","dev"` 在 Windows 下**起不来**（npm 是 .ps1/.cmd 包装，Start-Process 拿不到），日志文件会是空的，端口也不通。

**正确做法**——直接调 node 跑 vite 入口：

```powershell
$node = (Get-Command node).Source
$vite = Join-Path (Get-Location) "node_modules\vite\bin\vite.js"
Start-Process -FilePath $node `
  -ArgumentList "`"$vite`"","--port","5211","--strictPort" `
  -RedirectStandardOutput "$wd\_web.log" -RedirectStandardError "$wd\_web.err" `
  -WindowStyle Hidden
```

### 1.2 探端口：不要靠日志判断

日志经常为空或滞后。**直接用 TcpClient 探**：

```powershell
foreach ($p in @(5211,8811)) {
  $s = New-Object Net.Sockets.TcpClient
  try { $s.Connect("127.0.0.1",$p); Write-Output "$p OPEN" }
  catch { Write-Output "$p closed" } finally { $s.Close() }
}
```

### 1.3 启动命令会「假死」在工具层

`Start-Process ... -WindowStyle Hidden` 后面如果紧跟 `Start-Sleep` 和端口探测，整条命令有时会返回 `Unknown: ChildProcess.kill (...)` 而无输出——**但服务其实已经起来了**。

遇到这种情况：**把「启动」和「探测」拆成两次工具调用**，不要在一条命令里串起来。

### 1.4 用 python 启后端

```powershell
Start-Process -FilePath "python" -ArgumentList "-m","uvicorn","<mod>.app:app","--port","8811" `
  -RedirectStandardOutput "$wd\_api.log" -RedirectStandardError "$wd\_api.err" -WindowStyle Hidden
```

英语案是 `node voceng/server.js`；Go 案要**先 cd 进模块目录**再 `go run .`（`go test ./...` 同理，在项目根跑会报 `directory prefix . does not contain main module`）。

## 二、测页数与渲染检查

### 2.1 Word/WPS COM 测页数（唯一可靠方式）

LibreOffice 对**中文路径**会静默失败（转不出 PDF），不要指望它。工作区已有脚本可直接用：

```powershell
# _pages.ps1 —— 测页数
pwsh -NoProfile -File "_pages.ps1" -DocxPath "<绝对路径.docx>"
# 输出：PAGES=73 via Word.Application
```

脚本要点：按 `Word.Application` → `KWPS.Application` → `WPS.Application` 依次尝试，`Documents.Open($path,$false,$true)` 只读打开，`Repaginate()` 后取 `ComputeStatistics(2)`。

**不要并发启动多个 Word/WPS 进程**，会互相干扰。

### 2.2 导 PDF 供逐页渲染检查

```powershell
# _topdf.ps1 —— 导出 PDF（仅用于检查，交付目录不留 PDF）
pwsh -NoProfile -File "_topdf.ps1" -DocxPath "<docx>" -PdfPath "<pdf>"
```

然后渲染：

```powershell
& $env:MIMO_PYTHON -m pypdfium2_cli render "<pdf>" --output <目录> --format png --scale 1
```

### 2.3 逐页空白量化

按**块**扫描（30px 块），不要按行扫描——按行会被细线干扰，误判率极高。同时算「尾部空白占页高比例」：

- 尾部空白 > 45% → 该页需返工
- 有空白页、整页仅一行 → 直接返工

**但最终以肉眼核对截图为准**：算法会把纸底浅色、图表留白误判为空白。水利案算法报 50%+ 的页，肉眼看是正常的表格页。

## 三、Playwright 截图采集（最容易返工的环节）

### 3.1 顺序不能颠倒

```
先重置数据库 → 再按状态链操作 → 边操作边录元数据
```

### 3.2 【最大坑】截图前必须重置数据库

反复跑截图脚本会让库停在某个中间态。**后果**：后续操作"已是目标状态"，点击后页面无变化，你会误以为是元素定位错了，反复调试无效。

**症状**：toast 提示操作成功，但状态列/判定框数值不变。

**修复**：写重置脚本直接调项目的 seed。Python 案：

```python
import sys, importlib
sys.path.insert(0, r"<项目路径>")
store = importlib.import_module("<pkg>.store")
seed = importlib.import_module("<pkg>.seed")
db = store.connect()
try:
    seed.reset(db); db.commit()
    print("reset ok")
finally:
    db.close()
```

Node 案：`node voceng/seed.js`。

### 3.3 起点要选「有变化空间」的状态

初始已是「已锁定」的单据，再点锁单看不出变化。应挑初始「对账中」的记录来操作。

水利案的具体做法：进计价锁定页后**先 selectOption 切到一张低资格分的单**（初始对账中），再改参数重算，这样资格分从 0.72→0.97、状态从对账中→已申报，变化明显。

### 3.4 输入框定位：别用 `input[type="number"]`

Vue 的 `v-model.number`、Svelte 的 `v-model.number` **渲染出来都是 `type="text"`**。

正确做法：`.stage input` 或 `.stage select` 配合 `nth(i)` 按位置定位。

**索引错位陷阱**：页面顶部一排输入框时，`nth(3)` 和 `nth(4)` 很容易搞混（水利案把坍落度写成 Qmin，导致整组截图无效）。**用 probe 脚本先打印 `evaluateAll` 的 name/value 列表确认**。

### 3.5 相邻图差异像素占比小是正常的

变化往往集中在状态列、判定框、计数区等局部，整图占比可能只有 0.2%。

**判定标准是「状态确实变了」**，不是像素占比高。核对项：

- toast 文字变了
- 状态列文字变了（待处理→处理中）
- 计数/指标数字变了
- 判定框配色变了
- 留痕条数增加了
- 三维场景着色变了

**不合格的**：只换时间、只换滚动位置、只换光标、仅短暂 toast 且无状态残留。

用 `_shotdiff.py` 先筛出 <1.2% 的组，再**逐张肉眼核对**确认是否真实状态变化。

### 3.6 元数据与图片必须数量对齐

脚本中途崩溃会丢 manifest（水利案前 30 张的元数据就丢了）。

**修复**：用正则从采集脚本源码里反向重建 manifest：

```python
pat = re.compile(r'shot\(\s*"([^"]+)"\s*,\s*"([^"]+)"\s*,\s*"([^"]+)"\s*,\s*"([^"]+)"\s*,\s*"([^"]+)"\s*,\s*"([^"]+)"\s*(?:,\s*(true|false)\s*)?\)', re.S)
```

然后比对图片文件列表，报「缺图」与「无元数据的图」。

### 3.7 补采新页面截图

页面新增后要补采，**合并时按 id 排序去重**：

```python
ids = {r['id'] for r in main}
for r in extra:
    if r['id'] not in ids: main.append(r)
main.sort(key=lambda r: r['id'])
```

### 3.8 采集规格（固定）

```javascript
const p = await b.newPage({ viewport: { width: 1920, height: 1080 }, deviceScaleFactor: 1.5 });
// → 原图 2880×1620
```

浏览器启动：`chromium.launch({ channel: "chrome", headless: true })`。**禁止 `npx playwright install`**。

在 `_soft_work\shotkit` 目录下跑（那里有 `node_modules/playwright`）。

## 四、页面密度返工

### 4.1 只做主要功能页

**不必每页都追空白率**。三维页的空白是天空背景，属正常，不做处理。优先修：主判断页、各业务录入页、单据页。

### 4.2 补密度必须是真实信息区

补的是**真实数据、真实统计、真实派生值**，不是加填充、不是拉大间距。常用补法：

- 判据/阈值台账（把分档门槛写在页面上）
- 当班统计 KPI（总数/各状态数/极值）
- 分档条（带百分比）
- 明细表（比主表更多字段）
- 动作分布（按动作统计条数）
- 参数读数带（当前选中项的全部字段）

### 4.3 栅格冲突排查

补面板后若出现错位或多余空行，**显式指定每区的 `grid-column` / `grid-row`**，不要依赖自动流：

```css
.tree      { grid-column: 1 / 2; grid-row: 1 / 3; }
.table-wrap{ grid-column: 2 / 3; grid-row: 1 / 2; }
.seg-wrap  { grid-column: 2 / 3; grid-row: 2 / 3; }
.cond      { grid-column: 3 / 4; grid-row: 1 / 3; }
```

### 4.4 Vue 模板插入区块时注意闭合顺序

往 `.vue` 模板里插新 `<section>` 时，**极易把 `</template>` 插到中间**，报错形如：

```
[plugin vite:vue] src/pages/Xxx.vue (89:3): Invalid end tag.
```

**自查方法**：统计标签配对。

```powershell
$t = [IO.File]::ReadAllText($path, [Text.UTF8Encoding]::new($false))
"template open=$(([regex]::Matches($t,'<template>')).Count) close=$(([regex]::Matches($t,'</template>')).Count)"
"div open=$(([regex]::Matches($t,'<div')).Count) close=$(([regex]::Matches($t,'</div>')).Count)"
```

**修复**：按行重排区块顺序，而不是逐段 replace（换行符差异会让 `Contains` 匹配失败）。

### 4.5 改完必须重跑构建

`npm run build` 会同时做类型检查（`vue-tsc --noEmit` / `tsc --noEmit`），能挡住大部分低级错误。类型报错时优先修签名，不要用 `as any` 绕过。

## 五、代码文档：字号是页数的杠杆

### 5.1 不必堆代码量

**页数达标靠字号 + 行距调节**，不要为了页数硬写无意义代码。

水利案实测（2718 行源码、60 个文件）：

| 字号 | 行距 | 实测页数 |
|---|---|---|
| Consolas 11.0pt | 250 | 56 页 |
| Consolas 12.5pt | 250 | **73 页** ✓ |
| Consolas 13.0pt | 276 | 76 页（超上限） |

**调页数流程**：生成 → Word 实测 → 调字号 → 再测，一般 2–3 轮收敛。

### 5.2 只收后端与算法

剔除：CSS/SCSS/LESS、HTML 模板、Vue/Svelte/React 组件的 template/JSX 与样式段。

**验收**：搜一遍代码 TXT，确认无 `background:` / `display: flex` / `<template>` / `scoped` 等前端样式或结构行。

### 5.3 硬性要求

- **零注释**（中英文全去）——正则剥 `#`、`//`、`/* */`、`""" """`
- **无页眉/页脚/页码**——`for hdr in (sec.header, sec.footer): hdr._element.clear()`
- **开头直接以源码开始**——禁止 `// 文件归档:` 归档头、禁止中文说明块
- **边距紧凑** 18–19mm

**验收**：

```python
print('header 段落:', [p.text for p in s.header.paragraphs])  # 应为 []
print('footer 段落:', [p.text for p in s.footer.paragraphs])  # 应为 []
print('前 12 行:', [p.text for p in d.paragraphs[:12]])       # 应直接是代码
```

## 六、操作手册排版

### 6.1 基线参数（水利案实测 44 页）

- A4 竖版，边距 20mm
- 正文 13pt，行距 2.0
- 图片宽 6.1 英寸（高不超过 4.6 英寸）
- 图注 10.5pt 斜体，居中
- 每图后紧跟 3–5 行说明

### 6.2 首页纯文字

第 1 页不放大图。水利案的首页结构：标题 + 版本号 + 四段开头（业务线 / 四个判据量 / 手录说明 / 截图来源）。

**开头格式轴每案重选**，禁止连续两案同构。生成前先读 `recent-system-fingerprints.md` 选方向。

### 6.3 手册章节按业务流编译

不要套「软件定位/安装/登录/逐页」万能顺序。水利案的章节：

```
入席 → 截流窗口台判断线 → 闸段工序 → 戗堤高程 → 仓面浇筑
→ 验工对账 → 计价锁定 → 质量验收 → 三维现场 → 专业计算台
→ 窗口归档 → 异常回退 → 数据字典 → 开发留痕 → 常见问题 → 运行环境
```

注意：**异常回退、数据字典、常见问题穿插在业务章节之后但仍在正文中**，不要全堆到附录。

### 6.4 正文措辞

`必须/不得/禁止/不允许` → `需要/不会/不应/暂不支持`。

### 6.5 体积控制

水利案 48 张 2880×1620 的 JPEG（quality 92）→ 手册 16.94MB，在 20MB 限内。

超限时：JPEG quality 降到 80、PNG 转 JPEG、清理未使用媒体，**不要压到文字不可读**。

## 七、目录收敛

### 7.1 根目录只留四项

```
[全称]申请表.txt
[全称]代码.docx
[全称]操作手册.docx
[全称]-源代码/
```

**不产出 PDF。**

### 7.2 什么进源代码目录

- **源码**：`src/`、后端目录、`public/`
- **工程配置文件**：`package.json`、`package-lock.json`、`tsconfig*.json`、`vite.config.ts`、`requirements.txt`、`pytest.ini`、`index.html`、`svelte.config.js`
  - 这些是**工程文件不是留档文档**，允许留在 `-源代码/` 根（参照项目同样如此）
- **运行期文件**：`*.sqlite3`

### 7.3 什么进留档子目录

所有留痕文档一律进 `-源代码/<留档子目录>/`：

- 设计说明、`IMPLEMENT.md`
- 研发日志、提交清单、变更台账、发布记录、审计台账、验收记录
- `留档元数据.json`
- **手册源稿、代码文档源稿、截图采集脚本、截图状态链清单**（水利案也放了这些）

### 7.4 什么移进备份

`node_modules`、`dist`、`.pytest_cache`、`.vite`、临时生成脚本 → 移到 `_软著整理备份/<案名>-<日期>/`。**移不删**，便于复用。

### 7.5 验收口径

```python
# 留档类文档不得游离在源代码根
stray_md = [p.name for p in src.iterdir() if p.is_file() and p.suffix == '.md']
stray_doc_json = [p.name for p in src.iterdir() if p.is_file() and p.name == '留档元数据.json']
# 两者都应为空
```

## 八、台账维护

### 8.1 记入近案指纹

定稿后往 `_soft_work/recent-system-fingerprints.md` 追加条目，含：

- `variationId`、信息架构、应用壳、首页轮廓、三维族、后端拓扑、前端栈
- 手册方向（方向族 + 方向描述）
- 签名元素、状态机、色板
- 交付数据（截图张数、代码页数、手册页数）
- **禁止后续近案复用**清单

### 8.2 删掉阶段一的「在建」条目

阶段一往往已留了一条「（在建）」记录。定稿后**必须删掉它**，否则台账重复、后续选方向时会误判。

**注意**：删除时用**按行切片**而不是字符串 replace——文件换行符（CRLF/LF）差异会让 `Contains` 匹配失败：

```powershell
$lines = [IO.File]::ReadAllLines($f, [Text.UTF8Encoding]::new($false))
$out = $lines[0..($start-1)] + $lines[($end+1)..($lines.Count-1)]
[IO.File]::WriteAllLines($f, $out, [Text.UTF8Encoding]::new($false))
```

## 十、给并行对话派活时的注意

多案并行时，每案开一个独立对话，**首条消息里必须包含**：

1. 指向 `_soft_work/四案并行交接说明.md`（环境、坑、门禁、脚本索引）
2. 该案的已知信息：技术栈、端口、后端入口、测试命令、登录凭据、页面清单、三维模型清单、网图数量
3. 交付目标（八步，与 SKILL.md 门禁对齐）
4. 本文提到的关键坑（尤其「截图前重置数据库」「输入框定位」）

**踩过的教训**：交接消息里的路径别手打，容易写错（水利案交接时把 `_soft_shots\sigtrace` 写成了 `_soft_shots\sigtrace` 之外的错误路径，只能补发更正）。建议直接从项目实际目录复制路径。
