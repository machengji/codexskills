# 设计与实现约束（硬门禁 + 示例）

> 本文件只保留硬门禁和示例；具体实现由本项目业务流决定，禁止照抄示例。

## 硬门禁（强制）

1. **单点业务闭环**：围绕系统全称选一个现实生活中可执行的单点业务，形成“现场影像进入、判断处理、人工操作、结果变化、复查沉淀”的闭环。
2. **三维是默认交付物**：须达到“工业现场级”数字孪生门槛（整厂/产线/仓储观感），不得省略、用静态图代替，或用虚空单机冒充。数字只作参考，不写死；三维至少出现在 3 个菜单，每个菜单至少 1 种不同模型（共至少 3 种，禁止同一模型换色/换视角冒充）。
3. **中文与编码**：所有可见文字、错误提示、按钮、图表标题、空状态和注释使用自然专业中文；文件使用 UTF-8 无 BOM；中文直接存储，禁止 Unicode 转义。
4. **软件全称逐字显示（强制）**：登录页、顶栏、导航夹脊、浏览器标题与页面可见位置的软件名称必须与用户提供的软件全称逐字一致，禁止自行简写、缩写、改字、加字、截断、别称和“工作簿/工作平台/分析系统”等替代词，禁止改用英文名/英文翻译或中英混写；用户给什么名称就逐字显示什么名称。
5. **界面必须创新且好看**：先走 frontend-design 精修，主次清晰、色彩克制、字体成对、材质统一、对比足够、首屏有签名元素；禁止脏乱堆叠、万能霓虹、无意义玻璃拟态、AI 默认脸和模板脸后台。
6. **独立开发与反换词**：禁止复制旧项目或同级案例后仅替换软件名、行业词、颜色、图标、文案；路由树、Store 形状、领域类型、状态枚举、专属页面文件、核心业务函数必须本项目新写；共享只能下沉到无业务语义的原子组件。
7. **页面功能复杂度（工业诊断台级）**：首屏 ≥3 个并发工作区（对象/工况器、中央解析舞台、规则/结果/风险区）；有效操作入口 ≥16，页面专属动作 ≥5，且有业务语义反馈；全站 ≥5 页达到高密度诊断台加强标准。
8. **操作必须有真实后果**：按钮不能只有提示框；每次交互至少触发一个真实结果（切换图像版本、更新重点区域、更新模型姿态、更新任务卡、打开抽屉/弹窗、生成可下载成果、记录操作并允许查看前后状态）。
9. **1920 宽度与页面密度（强制）**：所有页面按 1920×1080 设计，首屏铺满全宽，禁止大面积空白/留白；每页至少 3 个并发工作区 + 信息密集区，表格/列表/卡片/弹窗填满可用宽度。

## 示例（仅示意，禁止照抄）

### 名称语义 → 界面后果映射

| 名称语义 | 界面后果 |
|----------|----------|
| 核心对象 | 决定舞台形状与组件几何 |
| 关键动作 | 决定阅读方向、导航和动效 |
| 真实场所 | 决定材质、光线与空间密度 |
| 判断结果 | 决定状态色与图表表达 |
| 主要使用者 | 决定信息层级 |
| 现场工具 | 决定控制器与按钮形式 |

### 前端模拟行为链路（改写为系统专属业务词）

```text
载入现场影像
→ 检查画面
→ 执行前端图像处理
→ 发现或标注重点区域
→ 在模型中定位或模拟
→ 制定并执行处置动作
→ 载入复查结果
→ 比对变化
→ 保存过程记录与成果
```

### 按钮文案示例（动作 + 对象）

- 校正当前画面
- 锁定观察区域
- 映射至立体位置
- 建立复查节点
- 切换告警高亮

## 实现验收要点

- 页面数量、模块结构、技术栈、文件命名、目录拓扑由业务流决定，只卡硬下限（正文 ≥30 张唯一截图、51–60 页、后端/算法占比 ≥60%）。
- 已完成 frontend-design 视觉精修方案并写入设计说明。
- 已与同级 3–5 个案例完成十维防重复比较，至少七项明显不同。
- 每页有效操作入口 ≥16、专属操作 ≥5，并满足工业诊断台级并发工作区与业务语义反馈。
- 中国境内真实网图案例 ≥6 已本地化，台账含来源/许可/`country: 中国`/省市地点/地点依据/名称关联/页面角色；外国场景图片为 0（用户明确指定除外）。
- 核心影像在首屏链路中可载入，且有可见处理过程。
- 核心三维工作台首屏即有可识别的高级分层组合模型（非空画布、非单 primitive、有阴影接地）；三维至少出现在 3 个菜单，每个菜单至少 1 种不同模型（共至少 3 种）。
- 页面按 1920×1080 设计，首屏铺满、无大面积空白/留白。
- 所有界面为中文且不出现禁止信息；全局无滚动条，局部滚动逻辑稳定。
- 没有伪代码、占位图片、假按钮、空白页面或无关菜单。
- 系统名称不同会导致场景、菜单、图像、模型、术语和流程显著不同。
- 已按落地循环完成多轮构建与三维门禁复验并写入 `验收记录.md`。
