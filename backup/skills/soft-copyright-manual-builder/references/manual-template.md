# 操作手册标准模板结构（硬门禁 + 示例）

> 本文件只保留硬门禁和示例；具体章节结构由本项目业务流决定，禁止照抄示例。

## 硬门禁（强制）

1. **真实开发**：手册只能描述当前项目实际可运行的系统；所有截图只能来自当前项目实际运行的浏览器/客户端画面；禁止虚拟图、生图、无关图片、拼接或改图。
2. **反模板化**：章节、步骤、异常、图注必须来自当前项目真实页面与专属操作；禁止套用固定“万能后台手册”后批量替换模块名；通过“换行业测试”。
3. **页面自主创新覆盖**：登录页必须单独成章或单独小节；首页和每个业务页必须按真实职责单独记录入口、专属动作、状态反馈、异常回退和与相邻页的布局差异；禁止用“其余页面操作相同”跳过。
4. **开发留痕**：手册必须包含“开发留痕”章节/分节：版本记录、迭代记录、测试记录、验收记录、缺陷修复记录、数据字典、操作留痕说明，以及版本发布 / PR 审计 / 代表性提交 / 研发日志摘要（引自项目留档目录，目录名/文件名每案自主编译，禁止固定叫「研发留痕」）。
5. **去 AI 味**：遵守 [操作手册去AI味与研发留痕](操作手册去AI味与研发留痕.md) 与 [去AI味自然写作编译规范](去AI味自然写作编译规范.md)；禁用词清零；换行业 / 同级换词 / 公开通用句三项通过。
6. **截图状态链（生成期前置）**：遵守 [操作手册截图状态链协议](操作手册截图状态链协议.md)；状态链由本项目业务自主编译、不套固定链，且必须在系统生成期就按“非静态页、操作后必有可见状态变化”写进代码，截图只是录制真实状态变化；每张截图都是真实操作后的新状态，每图配 3–5 行短人话说明；操作步骤与截图严格一一对应，禁止无截图的长步骤清单。
7. **页数与排版**：第 1 页纯文字首页（无封面图），实测 42 页以上；无空段撑页、无硬分页灌水、不靠大量文字填充页数；正文连续段落，禁止用表格拆字导致“一字一格”。目录排版（点线页码/纯文本目录/章节编号风格）属变量层，随本案叙事方向自主编译，禁止连续两案同构。
8. **反重复文案**：同一完整句子在全手册最多出现 1 次；连续 3 段以上仅序号不同、其余文字相同，直接判定不通过并返工。
9. **文件体积**：最终 `[软件全称]操作手册.docx` 单个文件 ≤20MB；超限时压缩内嵌图片（JPEG 质量 ≥80、PNG 转 JPEG、清理未使用媒体与元数据），禁止把截图压到模糊或文字不可读；压缩后复核体积与页数。
10. **软件名称逐字一致**：手册首页、章节标题、图注与正文中的软件名称必须与用户提供的软件全称逐字一致，禁止简写、缩写、改字、加字、截断或改用英文名/英文翻译；与页面显示、申请表、代码文档同名。
11. **1920 宽度与页面密度**：所有页面按 1920×1080 设计，首屏铺满、无大面积空白；截图必须来自 1920 全宽页面，禁止窄屏拉伸或居中留白。
12. **步骤与截图严格对应**：每个操作步骤必须有对应截图，截图紧跟对应步骤；禁止无截图的长步骤清单（如「XX操作清单」连续编号步骤）；纯说明、异常拦截、数据字典、环境部署、附录等非操作步骤内容可无图。

## 示例（仅示意，禁止照抄）

### 示例 A：任务路线式章节

```text
## 第X章：[模块名称]
### X.1 模块概述
[功能简介 + 核心价值 + 适用场景，150-250字]
### X.2 前置约束
• [前提条件1]
• [前提条件2]
• [前提条件3]
### X.3 详细工步
1. [定位 → 动作 → 反馈，40-70字]
   [仅当界面状态与上图明显不同时配截图]
   [图注X-1]
2. [每个操作步骤紧跟对应截图；无独立截图的步骤并入上一步描述，不单独编号]
### X.4 异常拦截机理
【异常情况1】[原因及解决方案]
【异常情况2】[原因及解决方案]
```

### 示例 B：角色分工式章节

```text
## 第X章：[角色/岗位操作]
### X.1 角色与权限
[谁在什么条件下进入本模块]
### X.2 操作入口
[菜单/按钮/字段定位]
### X.3 操作后果
[提交/审核/归档后状态变化]
### X.4 异常与回退
[失败提示、恢复方式、复查路径]
```

> 章节结构可按业务流选：任务路线、角色分工、案例叙事、决策树、班次记录、生命周期、异常优先、对象卡片等。只要求覆盖：入口 → 动作 → 反馈 → 异常 → 回退。

## 方向族参考清单（只作参考，禁止轮换复用）

> 每案从软件全称+业务场景自主编译叙事方向，方向族只帮助“想不出方向”时打开思路；**禁止按清单顺序轮换**，也禁止连续两案同方向族。台账记录两字段：方向族 + 方向描述（描述必须自带开头格式特征，如 `值守链路视角｜四段标签式：业务定位/适用角色/单点判断/不适用范围`、`罐区风险闭环视角｜散文式软件定位章节`）。

| 方向族 | 适用业务特征 | 开头段示例写法（仅示意） |
|---|---|---|
| 值守链路 | 监测/预警/值班/巡检类 | 从“谁在什么班次盯什么屏”切入，角色+班次+链路 |
| 风险闭环 | 安全/隐患/整改/处置类 | 从“一个隐患从发现到销号”切入，闭环阶段叙事 |
| 文书流转 | 审批/政务/流程/签批类 | 从“一份文书走几个环节”切入，文书元数据式首页 |
| 数据流 | 采集/分析/计算/统计类 | 从“数据从哪来到哪去”切入，数据管道叙事 |
| 生命周期 | 设备/资产/台账/档案类 | 从“一台设备从投运到退役”切入，阶段档案叙事 |
| 现场工序 | 制造/施工/作业/工艺类 | 从“现场一道工序接一道工序”切入，工步清单叙事 |
| 诊断决策 | 故障/诊断/方案/评估类 | 从“一个异常如何被判定”切入，判据+结论叙事 |
| 巡检排程 | 巡检/排程/任务/计划类 | 从“一张排程表如何被消化”切入，任务闭环叙事 |
| 仿真推演 | 仿真/预测/推演/优化类 | 从“一次推演从设参到出结果”切入，实验记录叙事 |
| 交易结算 | 交易/结算/账务/核销类 | 从“一笔业务如何对账核销”切入，单据流水叙事 |

- 开头段格式指纹 = 方向族 + 方向描述（含开头格式特征）；生成前读台账选方向，定稿后按台账复核，连续两案不得同构。


## 密度参考（硬下限）

| 指标 | 要求 |
|------|------|
| 总页数 | 42 页以上；Word/WPS 实测循环验页 |
| 截图 | 正文实际嵌入独立截图 ≥30 张；每张最多用 1 次 |
| 清晰度 | 页面按 1920×1080 设计；采集 1920×1080 @ 1.5x；原图宽度 ≥2880px；图宽约 5.0–5.3 英寸 |
| 同页步骤交互 | 同一页面多图必须来自真实操作；优先保持弹框/抽屉/详情面板可见 |
| 步骤与截图 | 每个操作步骤均有对应截图；无截图的长步骤清单为 0 |
| 文件体积 | 操作手册 DOCX 单个 ≤20MB；压缩以 JPEG 质量 ≥80 为下限，截图保持 100% 可读 |

## 禁止正文写文档制作说明（强制）

- 首页内容每案自主编译：软件全称、版本号必须出现；开头段格式与整本叙事方向从软件全称编译（方向族参考清单见下），格式自由（标签式/散文式/元数据式/问答式/场景式/对话式等）；适用角色、不适用范围等必要信息以任意形式出现，不能丢；**禁止连续两案同构**（如四段标签式「业务定位/适用角色/单点判断/不适用范围」不得连续两案复用）。
- 首页/正文禁止写：第1页为纯文字首页、配图策略、状态一自检、培训提示、全书看图路径、任何“按 skills 要求 / 为了凑页 / 为了图文均衡”的说明。
- 图注只写业务界面名或状态名，如 `跨度总览`、`测点接入-屏蔽通道后`、`证据归档-封存后`；禁止写 `状态一截图`、`唯一流程截图`、`用于证明后文也有图`。
