# 操作手册标准模板结构

> **总纲**：执行本模板前，必须同时满足 `SKILL.md` 中的 **「一体化前置门禁」与「通用修改要求（强制总纲）」G0–G10**：先验证名称驱动自主创新、登录页与全部业务页独立性，再执行无空行/流式紧排、Word/WPS实测51–60页、业务图片封面、安装章可跟做、步骤闭环、流程态截图、标准交付目录。

## 鉴别材料独创性（反模板化/反换词）

操作手册是软著文档鉴别材料，必须具备**独创性与代表性**，不能只满足页数和四级结构。

- 章节、步骤、异常、图注必须来自当前项目真实页面与专属操作；禁止套用固定“万能后台手册”后批量替换模块名。
- 禁止复用其他已完成案例手册正文，仅替换软件全称、行业词、按钮名。
- 每章概述要写本项目对象、判断目标与结果沉淀；详细工步必须出现本项目真实菜单/控件/状态词。
- 通过“换行业测试”：把软件名换成其他行业后，步骤与异常应明显不成立。
- 若页面本身模板化或源码换词，先退回系统实现，不得靠改写手册掩盖。

## 真实开发、开发留痕与团队化叙述（强制）

- 手册只能描述当前项目**实际可运行**的系统：每个页面、按钮、状态和流程都能在当前运行版本中复现；禁止虚拟图、生图、无关图片或无法端到端走通的流程。
- 所有截图只能来自当前项目实际运行的浏览器/客户端画面，禁止复用他案截图、拼接或改图。
- 手册以完整开发者视角组织：体现需求分析、设计评审、开发实现、功能验证、部署上线、文档交付的完整流程。
- 角色优先使用用户提供的**开发人员/团队**；未提供时用“需求组、研发组、测试组、部署组、文档组”或“开发组、项目组”等统称。禁止伪造用户未提供的公司名/著作权人。
- 手册必须包含“开发留痕”章节/分节：版本记录、迭代记录、测试记录、验收记录、缺陷修复记录、数据字典、操作留痕说明，以及版本发布 / PR 审计 / 代表性提交 / 研发日志摘要（引自项目 `研发留痕/` 或等价生成结果）；每条写清时间/版本、动作、结果与可复查位置。
- **去 AI 味**：遵守 `SKILL.md` R23 与 [操作手册去AI味与研发留痕](操作手册去AI味与研发留痕.md)；禁用总结腔/元叙述/万能宣传；通过换行业、同级换词、公开通用句三项检查。
- 代码注释只保留项目真实注释；不参与运行的算法说明（伪代码、公式、数据流等）可在附录单独给出并标注“说明性内容，不参与运行”。

## 页面自主创新与覆盖门禁

- 登录页必须单独成章或单独小节，写明业务准入语境、输入、验证反馈、失败回退和进入首页后的状态变化。
- 首页和每个业务页必须按真实职责单独记录入口、专属动作、状态反馈、异常回退和与相邻页的布局/阅读方向差异；禁止用“其余页面操作相同”跳过。
- 手册可以合并相近模块以满足页数，但不能合并掉页面职责、按钮后果或状态变化；截图不足时用真实步骤文字补足，不能用通用模板叙述冒充覆盖。
- 如果实际页面无法体现自主创新或只能靠标题区分，先退回 `vertical-image-system-builder` 修复系统，不得继续排版交付。


每个功能模块必须严格遵循以下四级结构：

```
## 第X章：[模块名称]
### X.1 模块概述
[功能简介 + 核心价值 + 适用场景，150-250字]
### X.2 前置约束
• [前提条件1]
• [前提条件2]
• [前提条件3]
• [前提条件4-7项]
### X.3 详细工步
1. [定位 → 动作 → 反馈，40-70字]
   [仅当界面状态与上图明显不同时配截图]
   [图注X-1]
2. [无新界面变化的步骤只写文字，不配图]
...
每模块 8-10 步，配图 2-3 张（禁止一步一图灌水）
### X.4 异常拦截机理
【异常情况1】[原因及解决方案]
【异常情况2】[原因及解决方案]
【异常情况3】[原因及解决方案]
```

需要时（复杂业务系统）可在概述后增加「角色与权限」「本章验收要点」，仍禁止灌水。

## 密度标准（硬性，与 SKILL 红线一致）

| 指标 | 要求 |
|------|------|
| 总页数 | **51–60页**，优先约55页；50页及以下或61页及以上均不合格；**Word 实测循环验页** |
| 截图 | **唯一 + 流程态**；正文约 **40–55张唯一截图**，另有1张不在正文复用的封面图；**每张最多用 1 次** |
| 清晰度 | 采集 1440×900 @ **2x**；嵌入 quality ≥85；图宽约 **5.0–5.3 英寸** |
| 每模块步骤 | **8–10 步**（禁止 15–18 步灌水） |
| 每模块截图 | **2–3 张**（仅挂在状态可区分的步骤下；优先操作后状态） |
| 每步字数 | **40–70 字**（定位→动作→反馈；写清菜单/按钮/状态） |
| 每模块异常 | **3–4 种** |
| 故障排除 | **10–12 条** |
| 交付格式 | **仅 Word `.docx`**（默认不生成 PDF） |
| 目录 | 左对齐标题 + 点线 + 右侧页码；无一字一空；无 AI 说明 |

## 配图与去重规则

1. 维护 `usedShots`：同一截图在**手册正文中**不得出现第二次（限制的是引用次数，不是磁盘删除）  
2. 禁止连续步骤贴同一主界面「看起来一样」的图  
3. 交互后若与主界面肉眼几乎相同 → **不要写入手册**（磁盘文件可保留备查）  
4. **同组截图必须有状态差异**：同一模块/业务闭环标为一个 `shotGroup`；2–3 张图要来自连续真实操作，并记录「前置状态 → 操作 → 后置状态 → 可见变化区域」。至少一处业务主体、状态标签、结果列表、详情内容、按钮可用性或联动视图发生肉眼可见变化。  
5. **禁止伪多态**：只有时间戳、数字刷新、随机数、鼠标位置、轻微滚动、动画帧、短暂 toast 或换文件名，不算状态变化；同组缩略图并排仍像同一张图时，删掉相似图或补做真实操作，不得写入手册。  
6. **优先流程态截图**：筛选后、提交/派单后、审核后、状态变更后、导出后、锁定/归档后；不能只有静态大屏  
7. 用实质文字撑页，不用重复贴图刷页  
8. 页数 <51：加长概述/异常/故障排除/读图说明，补流程图，或略增行距/图宽；**优先复用已有截图重生成 Word**  
9. 页数 >60：减少手册内重复引用、合并步骤、删除同组相似图，图宽可收到约 4.8–5.0 英寸  

## 截图缓存与复用（强制）

1. **默认保留截图**，交付后不要清空截图目录  
2. 推荐路径：项目根 `_soft_shots/`（优先）；历史兼容 `DELIVERED_DOCS/screenshots/`  
3. **改页数 / 改正文 / 改排版 / 改目录样式**：直接复用缓存重新打包 docx，**禁止全量重截**  
4. **仅缺图/坏图/用户要求刷新 UI** 时增量补截；禁止「先删光再重来」  
5. 脚本禁止默认 `开始就删除全部 jpg`  
6. 清理阶段只删一次性脚本/临时 HTML，**默认不删截图缓存**  
7. 截图缓存**不要**放进 `[软件全称]-源代码/`；最终文档放项目根，不放 `DELIVERED_DOCS` 

## 文字首页标准（强制）

1. **第1页独立成封面**：不得直接从目录或正文开始；封面与正文分 section，不靠空段、硬分页或大面积无内容留白撑页。
2. **素材优先级**：优先使用授权真实现场照片、真实系统主工作台高清截图或项目自有视觉素材。用户明确要求 AI 生图时，生成与软件业务一致的摄影级真实场景，并将原图与最终合成图保留在 `_soft_shots/`。
3. **AI 图片文字规则**：AI 原图中不得直接生成软件名称、版本号、菜单或说明文字，避免错字、乱码和伪文字；软件名称等必须在 Word 或本地后期合成时添加。
4. **真实感门禁**：人物、设备、办公、生产或数据操作环境必须自然可信。禁止卡通插画、简单图标拼接、低质量三维模型、无关行业图片、夸张霓虹科幻背景、品牌标志、水印及明显不符合业务的装饰图。
5. **占比与清晰度**：封面图占可视面积约55%–75%，保持比例安全裁切，不得拉伸、模糊、带红框或出现大面积无意义空白。
6. **封面文字**：至少显示软件全称、版本号、“使用操作手册”和一句简短业务定位；英文名称仅在用户或参考模板要求时保留。软件全称必须与申请表、代码文档及项目目录完全一致。
7. **正常手册封面排版**：封面必须像正常出版物或软件操作手册，而不是“白页上放一张截图”。标题信息、版本/文档类型、业务定位、主视觉和适用角色要形成清楚的信息层级；主视觉占可视面积约55%–75%，四周留出安全边距，避免标题贴边、文字与主体争夺视觉焦点、图片下方大面积空白、黑边白边异常或横向图片被压缩成窄图。生成图只负责主视觉，软件名称和版本号由 Word 或本地排版叠加。
8. **原三维场景生成封面**：用户要求使用原页面真实3D场景生成封面时，生成图必须沿用当前页面的机柜、计算节点、风道、热区、材质和视角母题，不得换成泛化机房或无关科幻场景；生成图内禁止直接生成软件中文名称，避免错字乱码。
9. **版式建议**:优先采用“顶部标题信息区 + 中下部业务主图 + 底部业务关键词/适用范围”，但应按行业调整配色和结构，禁止所有项目套用同一科技蓝模板。
10. **去重与许可**:封面图片单独记为 `coverShot`，不得在正文再次引用同一文件；外部素材必须保留来源与许可记录。

## 正文图片与图文平衡（强制）

1. 正文优先使用真实系统截图或高拟真业务操作图，每张图必须对应当前章节、具体步骤或可核对的状态变化。
2. 关键链路尽量覆盖“操作前 → 操作中 → 操作后”，或至少提供能看出筛选、提交、审核、导出、签章、归档等后果的流程态图片。
3. 优先截取完整业务页面；禁止只截侧边栏、导航栏、空白画布、无结果状态或与当前模块无关的局部区域。
4. 每张图前写操作目的和入口，图后写页面变化、结果含义、验收方法与下一步；纯图片、纯图注或无后果的展示图不计入有效配图。
5. 每个业务模块建议 8–10 个真实步骤、2–3 张唯一流程态图片；同组图片必须绑定不同状态和可见后果，避免连续多页纯图片或连续多页无业务图片。
6. 图片保持原始宽高比，正文嵌入宽约5.0–5.3英寸；不得拉伸、误用 twip、重复同屏或通过放大图片灌页。

## 标准章节列表示意

1. 系统概述 / 前言（可无图或 1 张总览）  
2. **安装部署与运行环境**（前置约束、可复制命令工步、验收要点、安装异常；强制，见 G3）  
3. 系统登录与安全准入（登录 / 可选登记 / 注销）  
4–N. 业务模块（按真实菜单，可合并相近模块；每模块要有可操作闭环）  
最后. 故障排除（无强制截图）  

不必固定 13 章硬凑；以覆盖真实功能且页数51–60为准。

```
前言  系统定位与业务主线 .......... 3

第二章  …… ..................... 8
```

- **左对齐标题 + 点线 tab leader + 右侧页码**  
- **禁止**两端对齐把标题撑成「一 字 一 空」  
- **禁止**目录上下写「本目录按…编排」「已纠正旧版」「阅读建议…」等 AI/过程说明

## 步骤撰文格式

```
1. 在左侧功能菜单栏中点击"生命体征趋势核验"，主区横幅切换为对应工作站名称，列表加载最近采样点。
[图X-1 生命体征主界面]

2. 点击时间窗"24H"过滤按钮，系统刷新序列，定位 SpO2 下降等明显波动点并记录时间戳。
[图X-2 24小时过滤后（状态须与上图可区分）]

3. 将低氧时间点与护理记录对照，确认是否已有吸氧/排痰干预描述（本步无新界面可不配图）。
```

**关键**：每步必须包含「定位 → 动作 → 反馈」；写清菜单名、按钮名、状态变化。  
**禁止**：每步只说「点击XX」；禁止无差异重复配图；禁止纯展示、无业务闭环。  
**文案**：业务手册语气；禁止 AI 腔、宣传腔、自我解释腔（如「已修复旧版…」）。

## 截图规范

- 命名：语义化且稳定，如 `s01-login.jpg`、`s13-vitals-24h.jpg`（便于下次复用）  
- 采集：viewport 1440×900，`deviceScaleFactor: 2`，JPEG quality ≥90  
- 嵌入：resize 约 1200–1400px 宽，quality 85–88，文档内宽约 **5.0–5.3 英寸**；`ImageRun` 必须带 `type`；transformation 用像素  
- 落盘：优先项目根 `_soft_shots/`，长期保留；勿写入 `…-源代码/`  
- 状态记录：每张图写入 `shotGroup`、状态名、真实操作和可见变化区域；同组相邻图片并排抽检必须能一眼区分  
- 状态类型（可选，且必须可区分）： 
  - 初始态  
  - 操作态（筛选/页签/滑块后）  
  - 结果态（提交/派单/审核/锁定完成）  

## 排版

- **流式紧密排列**：禁止空段撑页；段前宜 0、段后小间距；模块内不插硬分页灌水  
- 模块内不插硬分页，流式自然换页  
- 宋体正文 10–10.5pt，标题黑体；行距 1.3–1.5（line: 312–360）  
- 页眉：软件名称 + 版本号  
- 页脚：第 X 页（或兼容页码格式）  
- **文字首页（强制）**：第1页仅文字描述，含系统名称、版本号、使用操作手册、业务定位、适用角色；英文名称按用户或参考模板要求保留。**禁止**第1页放封面大图、系统截图或AI生图；禁止用重复句段撑满首页
- **正文截图位置**：系统截图只出现在对应业务章节；横向截图按正文宽度等比嵌入，不在首页使用。
- **正文单图原则**：禁止把多个系统截图拼成一张图。每张截图独立嵌入，图与图之间必须有“图示状态/读图提示”文字；连续状态要靠顺序排版表达，不靠拼图表达。  
- 文字首页与正文可同文档流式衔接；目录前允许分页，但首页本身无图  
- **正确 `docx` styles API**；正文连续段落，禁止用表格拆字导致「一字一格」  
- **对齐**：默认/标题/目录/步骤/图注左对齐；完整正文说明段才可两端对齐  
- 项目 `"type":"module"` 时生成脚本用 `.cjs`

## 禁止正文写文档制作说明（强制）

操作手册给最终用户阅读，不是给生成流程看的检查单。

### 首页可写
- 软件全称、版本号、使用操作手册
- 业务定位、适用角色
- 单点判断、不适用范围

### 首页/正文禁止写

## 反重复文案门禁（强制）

- 禁止用 `for i in range` 思路生成“说明1…N / 问题1…N / 规范1…N”且正文几乎相同的段落。
- 同一完整句子在全手册最多出现 1 次；允许专有名词重复，不允许整段模板句重复。
- 页数不足时，只能增加：逐页差异化工步、唯一截图读图、异常条件差异、安装故障、闭环验收点、真实研发留痕摘要（不同 PR/缺陷）。
- 交付前人工或脚本抽查：连续 3 段以上若仅序号不同、其余文字相同，直接判定不通过并返工。
- **去 AI 味与公开雷同**：执行 R23；禁用“综上所述/值得注意的是/如下所示/一站式赋能”等；换行业、同级换词、公开通用句三项检查通过。
